\section{相关工作}
\label{sec:related}

\paraf{大模型训练。} LLM 研究推动了可扩展、高效且鲁棒的训练技术发展~\cite{rasley2020deepspeed, shoeybi2019megatron, jiang2024megascale, zhang2025disttrain}，以满足这些模型巨大的计算需求。DeepSpeed~\cite{rasley2020deepspeed} 提供 Zero Redundancy Optimizer（ZeRO）~\cite{rajbhandari2020zero, rajbhandari2021zero, ren2021zero}，它在数据并行中将模型参数、梯度和优化器状态切分到参与 GPU 上，使 LLM 能够以可控内存消耗扩展。Megatron-LM~\cite{shoeybi2019megatron} 聚焦层内模型并行技术，切分每一层的参数和计算。流水线并行将连续一组层的参数和计算分配给每张 GPU~\cite{huang2019gpipe, narayanan2019pipedream}，将一个 batch 拆成 micro-batch，并以流水线方式处理这些 micro-batch。MegaScale~\cite{jiang2024megascale} 展示了结合张量、流水线和数据并行如何成为一种高效策略，用以前所未有的规模训练数十亿参数以上的大模型。

\parabf{专家混合训练。} 为应对训练先进神经网络的计算挑战，机器学习领域越来越多采用专家混合架构。随后，许多深度学习框架被提出，用于在多 GPU 集群上训练或推理 MoE。DeepSpeed-MoE~\cite{rajbhandari2022deepspeed} 通过模型架构设计和压缩技术显著降低训练成本。HetuMoE~\cite{nie2022hetumoe} 利用层次化 all-to-all 通信策略实现性能加速。SE-MoE~\cite{shen2022se} 聚焦使用 CPU 内存和 SSD 等异构资源进行可扩展高效训练。FasterMoE~\cite{he2022fastermoe} 引入一整套优化，如动态 shadowing、细粒度调度，以及避免拥塞的专家选择策略。Janus~\cite{liu2023janus} 为 MoE 模型提出以数据为中心的范式转变，目标是降低通信需求并提升训练效率。\revision{Tutel~\cite{hwang2023tutel} 为 MoE 模型提供动态方案，采用自适应并行和流水线。
然而，对于拥有数千亿参数的模型，其动态并行切换和层次化 all-to-all 可能造成显著开销。为避免这类开销，最新 MoE 训练系统~\cite{liu2024deepseek, liu2024deepseekv3} 使用辅助 loss 或 routing bias 进行负载均衡，并限制跨节点 token 分发。通过将每个 MoE 层映射到节点内，\sysname 消除了跨节点 token 分发。}

\revision{近期，DeepSeek-V3~\cite{liu2024deepseekv3} 为生产规模 MoE 模型训练引入了两个关键优化：DeepEP 用于高性能跨节点 all-to-all 通信，DualPipe 用于重叠通信与计算。由于跨节点 InfiniBand 带宽相对较低，DeepEP 将 token 分发限制在最多 4 个节点内，以保持恒定跨节点通信量，但这限制了其路由灵活性。相比之下，\sysname 将每个 MoE 层放置在节点内，以保证可高效路由到任意 top-k 专家。DualPipe 利用流水线并行在不同 micro-batch 之间进行通信-计算重叠，这需要存储 2$\times$ 的模型参数。相比之下，\sysname 的重叠发生在单个 micro-batch 的前向或反向传播内部，不引入额外内存开销，并且同时兼容带有和不带有流水线并行的系统。}

\parabf{长上下文训练。} Megatron-LM~\cite{shoeybi2019megatron, korthikanti2023reducing} 选择只沿序列维度划分特定操作，而用于训练长上下文模型的多种序列并行方法~\cite{li2024distflashattn, liu2023ring, li2021sequence, gu2024loongtrain} 也已被探索。Blockwise Parallel Transformer~\cite{liu2024blockwise} 基于 online softmax 计算，实现自注意力的分块计算和 FFN 融合。Ring Attention~\cite{liu2023ring, li2021sequence} 引入与自注意力计算集成的环式通信机制，以促进 key 和 value chunk 的交换。
% Compared to these methods, our Sequence Parallel Attention adopts several unique design choices to accommodate our target scenario: we distribute the FFN's weights with other parallelism given its significant memory footprint. We opt for a single all-gather operation to retain the full key-value pairs in memory, rather than re-communicating them during the backward pass. This strategy enables better performance in scenarios without extended context requirements.
我们采用 DeepSpeed Ulysses~\cite{jacobs2023deepspeed} 中 all-to-all 风格的 SP attention。由于它按 head 而不是序列长度划分注意力，因此通信量更低且计算模式更均衡。

\parabf{通信-计算重叠。} 一些框架~\cite{hashemi2019tictac, li2020pytorch, mahajan2023better, peng2019generic, pytorch_fsdp} 聚焦于在采用单一并行策略的分布式深度学习训练中重叠通信与计算。一些编译器风格工作~\cite{jangda2022breaking, wang2022overlap, pati2024t3} 提供 kernel 间细粒度重叠，但过度切分 GEMM kernel 可能导致 GPU 利用率较低。Centauri~\cite{chen2024centauri} 通过通信划分和层次化调度，增强采用 3D 并行的 LLM 训练中的通信重叠。类似 Centauri，我们的算子间通信重叠通过重排算子，将通信隐藏在独立计算之中。我们进一步通过算子内重叠隐藏关键路径上的通信，同时不损害 GPU 利用率。
