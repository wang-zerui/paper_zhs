\section{讨论}
\label{sec:discussion}

\heading{技能编译中的非确定性。}
与传统程序编译不同，技能编译以自然语言为输入，
因而在编译过程中内在地引入了一定程度的非确定性~\cite{wang2023selfconsistency}。
然而，执行技能的 LLM 与 CPU 等传统硬件~\cite{hennessy2019architecture} 有根本区别，
它对输入变化具有内在容忍度，使技能仍能正确执行。
此外，\sys 严格的编译优化阶段和回滚机制保证了
编译后的技能在大多数下游任务上能够持续带来稳定的性能提升。

\heading{能力覆盖范围。}
当前目录包含分属四类的 26 项原语能力，
足以覆盖我们分析的 15,063 个技能。
随着技能库增长，我们可以采用 \S\ref{sec:compiler:cap} 所述的迭代方法扩展原语能力集合。

\heading{编译成本。}
AOT 编译会调用 LLM，因而产生 token 成本。
不过，由于技能会在运行时被反复执行，
编译开销可以在多次调用之间摊销~\cite{gray1981transaction}。
此外，编译后的技能可以在用户与应用之间共享，进一步降低每个技能的编译成本。
