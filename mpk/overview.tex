\Sys is a multi-level superoptimizer for tensor programs with an arbitrary number of linear operators and at most one exponential operator on each path of the program, a class we termed {\em \lax tensor programs}. This section first formally defines \lax programs and then provides an overview of \sys.

%\paragraph{\lax program.} A \lax\footnote{\lax stands for \underline{l}inear with (at most) \underline{a}n e\underline{x}ponential.} program includes any linear operators\footnote{Note that element-wise division is considered a linear operator in \sys since the output is linear to the first input and to the inverse of the second input.} and at most one exponential operator.
% Formally, 

\if 0
\begin{definition}[Linear operator]
For a tensor operator $\er{op}$ with $n$ input tensors $I_1,...,I_n$, the operator is {\em linear} if its output is linear to all input tensors $I_k$:
\begin{align*}
    & \er{op}(I_1,\ldots,I_{k-1},X,\ldots,I_n) + \er{op}(I_1,\ldots,I_{k-1},Y,\ldots,I_n) \\
    & =\er{op}(I_1,\ldots,I_{k-1},X+Y,\ldots,I_n) \\
    & \alpha \cdot \er{op}(I_1,\ldots,I_{k-1},X,\ldots,I_n) = \er{op}(I_1,\ldots,I_{k-1},\alpha\cdot X,\ldots,I_n)
\end{align*}
where $X$ and $Y$ are tensors, and $\alpha$ is a scalar.
\end{definition}
\fi

\begin{definition}[\lax program]
For a tensor program $\m{P}$ with a computation graph $(\m{O}, \m{E})$, where $\m{O}$ is the set of operators in $\m{P}$ and $\m{E}$ denotes the set of tensors between operators, $\m{P}$ is a \lax program if (1) $\m{O}$ contains only linear, division, and exponential operators, and (2) every path in $\m{P}$ includes at most one exponential operator.
\end{definition}

\paragraph{\sys overview.}
\Cref{fig:overview} shows an overview of \sys, which takes a tensor program as input and produces an executable for the program. Similar to prior work~\cite{wang2021pet, ansor}, \sys first splits the input program into \lax subprograms to reduce the exploration space of each \lax subprogram while preserving most optimization opportunities.
%
For each \lax program, \sys's {\em expression-guided \graph generator} searches for possible \graphs using a given set of kernel, block, and thread operators.
%
The search is guided by the {\em tensor algebra expression} of \graphs, which allows \sys to effectively filter out \graphs that cannot yield the final output of the input \lax program.
All \graphs passing the expression filtering are considered as candidate \graphs. 

To examine the functional equivalence of a candidate \graph against the input \lax program, \sys's {\em probabilistic equivalence verifier} leverages novel theoretical results to quickly examine functional equivalence between two \lax \graphs and returns probabilistic equivalence: (1) for two equivalent \graphs, the verifier always verifies their equivalence; (2) for non-equivalent \graphs, the verifier detects that they are not equivalent with a certain probability.
%
\sys can repeat the probabilistic equivalence verification procedure multiple times to reduce the flash positive rate (i.e., two non-equivalent \graphs pass all random tests) to an arbitrarily low threshold.
%
This approach allows \sys to trade-off accuracy and efficiency of the verifier and can achieve arbitrarily high accuracy by repeating the verification steps.

For each verified \graph, \sys's {\em \graph optimizer} maximizes its runtime performance by considering potential data layout for all intermediate tensors at all of the kernel, thread block, and thread levels.
%
Finally, \sys returns an optimized tensor program based on the best discovered \graph for each individual \lax subprogram.
