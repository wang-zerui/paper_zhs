\section{第 1 章：摘要}
NVIDIA DGX SuperPOD 架构旨在为下一代 AI 工厂提供卓越性能、可扩展性与创新能力，服务企业、高校、科研机构与公共部门用户。该架构与 NVIDIA 内部核心研发系统保持“物理孪生”关系，即 NVIDIA 的基础设施软件、应用与支持流程会先在同构架构上完成验证。

\pandocbounded{\includegraphics[keepaspectratio]{images/92730ca277f1bd734c5bb9568ee0dc179ac2712a2d70b8c5c6fbbd894119f97e.jpg}}

本 DGX SuperPOD 参考架构（RA）基于搭载 Grace CPU 与 Blackwell GPU 的 DGX GB200 系统。本文介绍了定义 DGX SuperPOD 可扩展、模块化架构的关键组件。DGX SuperPOD 采用可扩展单元（SU）理念：每个 SU 包含 8 套 DGX GB200 系统，可实现任意规模的快速部署。文档还给出 SU 设计细节，以及 InfiniBand、NVLink、以太网 Fabric 拓扑、存储规格、推荐机柜布局与布线指导。

该 RA 融合多项 NVIDIA 前沿技术，帮助企业和行业构建自有 AI 工厂。为实现最佳扩展性，DGX SuperPOD 主要依赖以下关键技术与方案：

\begin{itemize}
\item NVIDIA DGX GB200 系统：AI 与 HPC 的高性能计算基石。
\item NVIDIA NDR（400Gbps）InfiniBand：高性能、低时延、可扩展互联网络。
\item NVIDIA Spectrum-4（800Gbps）以太网：面向存储连接的高性能低时延网络。
\item 第五代 NVIDIA NVLink：为加速计算中的 CPU/GPU 提供高速互联，支撑高强度通信模式。
\item NVIDIA Mission Control：统一的 AI 工厂运维与编排软件栈。
\end{itemize}

\section{第 2 章：DGX SuperPOD 架构}
DGX SuperPOD 架构由 DGX 系统、InfiniBand 与以太网网络、管理节点和存储共同组成。图 2.1 展示单个 SU（可扩展单元）的机柜布局。每个 SU 的热设计功耗（TDP）约为 1.2 兆瓦（MW）。通常建议数据中心满足或高于 Uptime Institute Tier 3，或 TIA942-B Rated 3、EN50600 Availability Class 3 等级标准，且具备并行可维护性与无单点故障能力。

每套 DGX GB200 采用液冷与风冷结合的混合散热设计，以应对机柜高热密度。由于 DGX SuperPOD（DGX GB200）是交钥匙级 AI 数据中心规模产品，NVIDIA 提供了数据中心设计指导，并将运行技术（OT）与 NVIDIA Mission Control 软件栈完成端到端集成。

\section{第 3 章：DGX SuperPOD 关键组件}
DGX SuperPOD 面向推理时代 AI 工厂的高需求而设计。AI 工厂需要高性能 GPU/CPU、先进网络与散热系统来支撑高强度计算负载，并在 AI 推理场景中实现更快、更精准决策。依托 NVIDIA 端到端加速计算平台，DGX SuperPOD 在提升推理性能的同时兼顾能效，帮助企业部署安全、面向未来的 AI 基础设施。

DGX SuperPOD 集成 NVIDIA 核心组件与经过认证的合作伙伴存储方案。借助可扩展单元（SU）理念，可将 AI 工厂部署周期由“月级”压缩至“周级”，从而缩短方案落地与产品上市时间。

DGX SuperPOD 面向本地部署（on-premises）：客户拥有并管理硬件，可部署在自有或托管数据中心中，并对集群基础设施与服务运行负责。

关键组件包括：
\begin{itemize}
\item NVIDIA DGX GB200 NVL72 机柜系统
\item NVIDIA InfiniBand
\item Mission Control 软件平台
\end{itemize}

\subsection{3.1 NVIDIA DGX GB200 机柜系统}
NVIDIA DGX GB200（图 3.1）是企业级 AI 算力平台，支持业务创新与优化。每套 DGX GB200 在机柜级提供 72 GPU 配置与突破性 AI 性能。NVIDIA Blackwell GPU 架构可将大规模 AI/ML 任务的计算周期从数月压缩到数天乃至数小时。

为适应高算力密度并提高机房空间利用率，DGX GB200 采用复杂的混合散热系统。GPU、CPU 等高功耗部件采用液冷，其余组件采用风冷。

NVIDIA 基础设施专家团队可提供从数据中心规划、系统部署到上电调试的端到端支持。

\subsection{3.1.1 DGX GB200 计算托盘}
DGX GB200 机柜系统的计算节点采用 72x1 NVLink 拓扑，即单一 NVLink 域内包含 72 张 GPU。每个机柜共有 18 个计算节点（托盘）。每个托盘包含两颗 GB200 Superchip，每颗 Superchip 含两张 B200 GPU 与一颗 Grace CPU。两颗 Superchip 通过 NVLink-C2C 芯粒互联桥接，可作为单一逻辑单元，由单一操作系统实例统一管理。

计算托盘集成四张 ConnectX-7（CX-7）网卡，用于跨机柜计算网络的 InfiniBand NDR（400Gbps）互联；并集成两张 BlueField-3（BF3）网卡，用于带内管理与存储网络的 2x200Gbps 连接。网络端口位于机柜前侧（冷通道一侧）。

每个计算托盘还提供 4x3.84TB E1.S NVMe（RAID0）本地存储，以及 1x1.92TB M.2 NVMe 系统盘。

\subsection{3.2 NVIDIA InfiniBand 技术}
InfiniBand 是高性能、低时延、支持 RDMA 的网络技术，已在高强度计算场景中验证超过 20 年。最新一代 NDR 单向峰值 400Gbps，端口到端口时延极低，并向后兼容前代规范。

InfiniBand 不仅具备高带宽与低时延，还提供自适应路由（AR）、SHARP 集合通信加速、SHIELD 动态网络自愈等能力，并支持 fat-tree、Dragonfly、多维 Torus 等拓扑，可构建超大规模网络 Fabric 与计算系统。

\subsection{3.3 NVIDIA Mission Control}
DGX GB200 SuperPOD 参考架构体现了构建高性能 AI 工厂的最佳实践。系统交付形式可按客户和用户需求灵活调整，统一由 NVIDIA Mission Control 进行管理。

NVIDIA Mission Control 是全栈软件解决方案。作为 DGX SuperPOD 体验的核心组成，它可优化开发者负载性能与韧性，通过自动故障处理保障连续可用性，并提供统一的集群级可观测与可管理能力。其关键能力包括：全栈韧性、预测性维护、统一错误上报、数据中心优化、集群健康检查与自动化节点管理。

Mission Control 融合 NVIDIA 管理海量系统的成熟技术，可帮助组织快速迈向 TOP500 级超级计算能力。

\subsection{3.5 设计要求}
DGX SuperPOD 通过紧耦合系统设计尽量降低全链路瓶颈，以获得最佳性能与应用扩展性；同时在整体层面保持灵活，便于融入既有数据中心环境。

\subsubsection{3.5.1 系统设计}
\begin{itemize}
\item 基于 SU（8 套 DGX GB200 NVL72）的模块化架构。
\item 经过完整验证的系统可扩展至 2 个 SU，更大部署可按客户需求定制。
\item 机柜级一体化设计，支持液冷高密度机柜快速安装与上线。
\item 采用通过 DGX SuperPOD 认证的合作伙伴存储设备。
\item NVIDIA Enterprise Support（NVEX）提供计算、存储、网络、软件全栈支持。
\end{itemize}

\subsubsection{3.5.2 计算 Fabric}
\begin{itemize}
\item 计算 Fabric 在顶层进行 rail 优化。
\item 采用均衡的全 fat-tree 架构。
\item 基于当前高性能低时延交换平台，并面向未来网络代际演进。
\item 全网使用可管理 NDR 交换机提升运维能力。
\item 支持最新 SHARPv3 特性。
\end{itemize}

\subsubsection{3.5.3 存储 Fabric（高速存储）}
\begin{itemize}
\item 与计算 Fabric 解耦，分别保证应用与存储性能。
\item 为每个 DGX GB200 计算托盘提供 2x200Gbps 线速能力。
\item 通过 RoCE 提供存储访问，降低 CPU 开销并提升性能。
\item 提供用户可访问管理节点对接共享存储。
\end{itemize}

\subsubsection{3.5.4 带内管理网络}
\begin{itemize}
\item 基于以太网，用于节点装配、数据传输、互联网访问和用户可达服务。
\item 计算/管理节点带内连接运行在 200Gbps，并通过绑定提升韧性。
\end{itemize}

\subsubsection{3.5.5 带外管理网络}
带外网络连接 BMC、BlueField BMC、NVSwitch 管理口（COMe）及其他需与用户物理隔离的设备。

\subsubsection{3.5.6 存储需求}
DGX SuperPOD 计算架构需与高性能、均衡存储系统配套，通常包括高速存储（HPS）与用户存储两类，分别针对吞吐/并行 I/O 及高 IOPS/元数据场景优化。

\paragraph{3.5.6.1 高速存储}
高速存储通过 RoCEv2 接入，来自 DGX SuperPOD 认证存储伙伴，建议具备：
\begin{itemize}
\item 面向多节点多线程读写优化的高性能、高可用 POSIX 文件系统；
\item 对 Grace 平台认证支持；
\item 原生 RoCE 支持；
\item 基于本地内存的透明缓存；
\item 基于本地闪存的透明读写缓存。
\end{itemize}
具体拓扑、容量与部件由认证存储伙伴在设计阶段确定。

\paragraph{3.5.6.2 用户存储}
用户存储区别于高速存储，通常通过带内网络暴露 NFS 共享，用于 home 目录、运维临时空间、以及高可用组件（如 Mission Control）所需日志与配置文件等。

其要求包括：
\begin{itemize}
\item 偏重元数据性能、IOPS 与企业级能力（不同于 HPS 的并行 I/O 优化）；
\item 基于以太网与 NFS 协议通信；
\item 100GbE DR1 连通性。
\end{itemize}

\section{第 4 章：网络 Fabric}
按 SU 构建系统可获得最高效率。若受预算或机房约束需部署非标准节点规模，仍建议按完整 SU 预留 Fabric（含叶交换机与叶-脊链路），将未使用部分留空，以保证最优流量路由与一致性能。

DGX SuperPOD 包含 5 类网络：
\begin{itemize}
\item NVLink 5
\item 计算 Fabric
\item 存储 Fabric
\item 带内管理网络
\item 带外管理网络
\end{itemize}

对应 4 类物理 Fabric：
\begin{itemize}
\item 多节点 NVLink Fabric（MN-NVL）
\item 计算 InfiniBand Fabric
\item 存储与带内以太网 Fabric
\item 带外网络
\end{itemize}

\subsection{4.1 多节点 NVLink Fabric（NVL5）}
每个 DGX GB200 机柜包含 18 个计算托盘与 9 个 NVLink 交换托盘。每个交换托盘配置 2 颗 NVLink 交换芯片，负责机柜内 72 张 GPU 的全互联。每张 B200 GPU 提供 18 条 NVL5 链路，分别连接至 18 颗交换芯片，合计可提供 1.8TB/s 低时延带宽。

\subsubsection{4.4.1 存储网络}
为兼顾高性能与高可用，每个 BlueField-3 DPU 的 4 个端口中有 2 个专用于存储访问。物理以太网通过专用 VXLAN 承载存储流量，终结于 DGX 存储网卡对应的 SN5600 叶交换机。每个 SU 另有一对 SN5600 叶交换机连接存储设备。

存储设备需支持 RoCE，并受益于拥塞控制、自适应路由等高级 Fabric 管理能力，从而实现低时延与高带宽。每个 SU 设计为到存储设备侧提供 16x800Gbps 无阻塞带宽；DGX 侧为轻度阻塞，阻塞比约 5:3。

\item 提供用户访问 Slurm 头节点与 Kubernetes 服务入口。

\section{第 5 章：存储架构}
海量数据是高精度深度学习模型开发的核心。数据规模持续增长，单模型训练数据量也在增加；不仅数据量，数据格式同样会影响访问效率，因此存储性能必须同步扩展。

DL 训练中的关键 I/O 行为是反复读取（re-read）。数据会在迭代训练中被重复使用。某些模型（如推荐系统）可在极少轮次内训练完成，推理阶段也可能高度 I/O 密集，因此读取性能非常关键。写性能同样重要：大模型训练周期长，需要周期性写入 TB 级 checkpoint 以实现容错，且该同步写入会阻塞训练前进。

理想情况下，首次读取后数据可被缓存，避免反复跨网访问。共享文件系统通常以内存作为首层缓存，从缓存读取可比远端存储快一个数量级。DGX GB200 还提供本地 NVMe，可用于缓存与数据暂存。

DGX SuperPOD 面向多类工作负载，不同模型/数据集对存储性能需求不同。高速存储应向所有节点提供共享数据视图，并针对小随机 I/O、单节点峰值与全局聚合性能优化。虽然 DL 训练多为读密集，写入 checkpoint 的峰值能力也不可忽视。对于 NLP/LLM 大模型，建议写性能至少达到推荐读性能的 $\frac{1}{2}$。

在最终确定性能与容量前，建议先完成工作负载画像。表 5.1 与表 5.2 给出参考。

\section{第 6 章：DGX SuperPOD 软件}
NVIDIA Mission Control 提供面向企业基础设施部署（如 DGX SuperPOD）的全栈数据中心软件方案，集成关键管理与运维能力，实现大规模统一控制。

\pandocbounded{\includegraphics[keepaspectratio]{images/ba1ed79f5a9846920ca96d94f42b6ff3b4146113788c09d9f32d948ba380e074.jpg}}

图 6.1：NVIDIA DGX GB200 SuperPOD 软件栈

Mission Control 软件栈由五层架构组成，从系统健康与诊断逐层扩展到高级集群管理能力。其基于 NVIDIA Base Command Manager（BCM）与 Run:ai，提供 SLURM 与 Kubernetes 的调度编排。遥测与可观测层提供系统洞察；验证与诊断层提供自治恢复能力，实现故障快速恢复。

Mission Control 还承担部署优化与系统健康监控，并与 BCM 协同完成集群装配和运维。软件栈中还包含 NMX，用于 NVLink 交换托盘的监控与控制。

Mission Control 带来的直接价值包括：
\begin{itemize}
\item 自动故障检测与自恢复：显著缩短停机时间，提高 GPU 利用率。
\item 负载迁移与资源分配优化：持续将任务调度到健康节点，提升吞吐与交付速度。
\item 基础设施与应用统一诊断：大幅缩短故障定位时间，降低 SRE/DevOps 运维负担。
\item 内存检查点与无缝恢复：自动从最近有效检查点恢复训练进程，减少重训损失。
\end{itemize}

\subsection{6.1 Run:ai}
Run:ai 作为 Mission Control 的组成部分，采用“控制平面 + 集群”分布式架构。控制平面支持跨组织多集群统一编排。在 BCM 管理安装中，控制平面部署在控制节点，集群组件部署在客户 Kubernetes 基础设施中，实现集中管理与就近执行。
