我们已经观察到一条清晰的演进路线：从独立的大语言模型（LLM），到基于 LLM 的单智能体系统（SAS），再到近来的多智能体系统（MAS）\citep{ke2025surveyfrontiersllmreasoning}。这一转变反映了现代任务日益增长的复杂性；这些任务往往需要持续推理、任务分解以及与其他专门智能体交互。早期 MAS 设计大多由人工构建，采用辩论等固定交互模式\citep{du2023improvingfactualityreasoning}。近年来，研究重心逐渐转向\textit{自动化 MAS 设计}：系统结构、智能体角色与交互关系均动态生成，因为人工指定不仅耗费大量人力，也难以扩展到新问题或新领域。
%\shafiq{Need to introduce automatic MAS with motivations.}





尽管自动化 MAS 已展现出很强的实证潜力，现有方法在几个重要方面仍存在局限：（1）\textbf{问题表述}：多数已有工作\citep{Ke2025MASZero,nie2025weakforstrong,hu2024ADAS}采用\textit{可执行代码}来表述智能体编排。基于代码的表述虽然灵活，但会带来显著开销；当子智能体及其连接关系变得更加复杂时（例如执行多轮搜索的智能体），这种方法也难以扩展，因为编排器在编排过程中往往需要分析、甚至复现完整的子智能体代码。
因此，这些方法通常局限于相对简单的子智能体，例如基于思维链（Chain-of-Thought，CoT）\citep{wei2022chain}和自洽思维链（Self-Consistency，SC）\citep{wang2023selfconsistency}的子智能体。（2）\textbf{训练}：许多现有方法高度依赖推理时自我改进或启发式搜索~\citep{zhang2024aflowautomatingagenticworkflow,liu2024dynamicllmpowered}。缺乏显式训练目标时，这种适应过程可能不稳定、优化方向错误，而且计算成本高昂。尽管近期一些研究已将训练引入 MAS 设计\citep{dang2025multiagentcollaborationevolvingorchestration,chi2025eraagenticorganizationlearning}，它们通常仍将编排建模为顺序决策过程，即每次增量添加一个组件，并通过多轮强化学习进行优化。这种范式在部分场景下有效，却会引入大量训练开销并鼓励局部的逐步优化，使编排器难以从全局视角推理 MAS 结构；（3）\textbf{智能体扩展原则}\citep{li2024more,qian2025scaling}。尽管 MAS 正被迅速采用，目前仍没有原则性的定量框架能够预测增加子智能体何时会提升性能、何时反而会降低性能。因此，实践者往往依赖启发式方法，这既限制了科学理解，也阻碍了实际部署。多智能体协作何时真正优于更简单的单智能体方案、何时只是增加复杂性，仍不明确\citep{kim2025sciencescalingagentsystems,huang2024large}。

我们认为，一个有效的自动化 MAS 应满足三个核心要求：（1）应有一个明确的\textbf{“MAS 程度（\masness）”}概念，用以刻画特定任务适合采用多大程度的多智能体协作，因为并非所有问题都能从 MAS 中获益。例如，我们的先导实验（\cref{sec:experiemnt}）表明，即便是 AIME 中颇具挑战性的数学任务，往往也很少受益于多智能体协作；（2）\textbf{编排机制应当灵活且可扩展}。即使子智能体高度复杂，该问题表述也应保持有效。特别是，编排器 LLM 应当\textit{只}关注高层推理与系统设计：它的职责是决定何时调用哪些子智能体，以及如何连接它们，而不是复现子智能体自身的内部行为；（3）\textbf{子智能体应由自己的目标定义，因此应拥有自己的上下文、工具和工作流}\cite{anthropic_subagents_2024}。
% \ryan{should we flag here that the design doesn't always beat SAS}
多数现有方法要么在\textit{LLM 空间}中定义子智能体~\cite{jin2025controllingperformancebudgetcentralized,estornell2025trainleaderhierarchicalreasoning,dang2025multiagentcollaborationevolvingorchestration}，通过切换不同骨干模型来区分子智能体，这会让编排器退化为单纯的 LLM 路由器；要么在\textit{提示词模板空间}中定义子智能体，使不同子智能体之间只有表层的提示词差异（例如在辩论中，不同角色往往仅通过修改角色描述来实例化：“你是一名批评者”与“你是一名支持者”）。此类定义忽略了工具使用与工作流，而这些同样是让子智能体围绕其目标形成专业能力的关键因素。

本文提出 \textbf{\ourframework}，
% \yf{why do we use ORCH instead of sth like Orchestra? The latter seems more memorable}, 
它将 MAS 编排表述为\textbf{函数调用强化学习（RL）问题}。在这一表述下，\textit{复杂度任意且面向目标}的子智能体（例如推理智能体和搜索智能体）被封装为可调用函数，其内部机制则被抽象隐藏。编排器只需通过调用 \texttt{create\_agent} 和 \texttt{create\_flow} 两个原语函数，决定何时实例化子智能体、创建哪些子智能体，以及如何连接它们。我们还在问题表述中引入了 \textbf{\masness}，用户可将其配置为\textit{低}（至多使用一个子智能体）或\textit{高}。基于这一表述，我们不再将 MAS 设计视为一系列决策，而是采用\textbf{整体式编排}，由编排器\textbf{在单个决策步骤中}生成\textit{完整}编排（对比见\cref{fig:main}）。

这种设计使编排器能够联合推理完整系统配置，而不是优化一连串局部决策。因此，学习到的编排反映的是全局协作模式，而不是执行顺序造成的影响。从学习角度看，它比多步方法更容易优化；多步方法会诱导局部的逐步优化，并受到长时域信用分配和误差传播的影响。因此，随着 MAS 复杂度上升，该设计能带来更稳定的训练和更好的可扩展性；其性能优于顺序式编排基线（\cref{sec:experiemnt}）也证明了这一点。它还带来了显著的效率提升（超过 10$\times$），因而位于帕累托前沿，如\cref{fig:parato_front}所示。

为了定量分析 MAS 在何时以及为何优于单智能体系统，我们提出受控基准 \ourbenchmark。它从\textbf{\depth、\horizon、\breadth、\myparallel 和 \robustness}五个维度刻画问题，从而能够系统且受控地评估 MAS 行为。

我们的分析得出了若干关键洞见。例如，我们发现多智能体协作的收益高度依赖于任务结构和底层 LLM 的能力。在这些洞见的指导下，我们在公共基准上开展实验，并证明恰当的 MAS 配置能够带来稳定的性能提升。

总之，本文的主要贡献如下：
\begin{itemize}[leftmargin=*,noitemsep,topsep=2pt]
  \item 我们为 MAS 编排提出一种新颖、可扩展且有效的强化学习表述，其中包含明确的 \textit{\masness} 概念，以及封装复杂子智能体的函数调用抽象。
  \item 我们提出专为 MAS 评估设计的受控基准 \ourbenchmark，可系统地实证分析 MAS 何时优于单智能体系统、何时并非如此。据我们所知，这是首个专门评估 MAS 收益的基准。
  \item 借助 \ourbenchmark，我们从三个分析方向研究广泛 MAS 配置下的收益，覆盖不同模型规模与家族中的三种编排器设置和五种子智能体设置。
  \item 在上述分析洞见的指导下，我们证明本方法在数学、多跳问答和多步搜索问答等公共基准上表现强劲，同时效率比强基线高出超过 \textit{10$\times$}。
\end{itemize}
