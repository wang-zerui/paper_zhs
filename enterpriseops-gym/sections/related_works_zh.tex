LLM 智能体基准大致可分为三类主题：通用工具使用与 API 评测、企业平台仿真，以及智能体规划与计算机使用。表~\ref{tab:related_works_comparison} 从关键维度总结了 \dataset{} 与它们的比较。

\paragraph{API 与工具使用基准}
早期基准工作着重测试智能体在通用开放领域中调用 API 和串联工具的能力。ToolLLM~\citep{qin2024toolllm} 在超过 16,000 个真实 Web API 上建立大规模评测；API-Bank~\citep{li-etal-2023-api} 提供了较小但可运行的系统，用于评估 73 个工具上的规划与检索能力。AceBench~\citep{chen2025acebenchwinsmatchpoint} 将规模进一步扩展至 4,538 个工具并支持动态多轮评估；$\tau$-bench~\citep{yao2024taubenchbenchmarktoolagentuserinteraction} 和 $\tau^2$-bench~\citep{barres2025tau2} 则引入用户模拟和拒绝鲁棒性作为评测维度。这些基准对衡量工具调用准确性作出了重要贡献，但仍以通用 Web 导向或开放领域 API 为核心；它们没有建模企业环境所特有的多系统、策略受限且有状态的工具生态，而这正是 \ours{} 所针对的场景。

\paragraph{企业基准}
第二类基准直接面向企业平台。单平台环境将范围限制在一个厂商内：WorkArena~\citep{workarena2024} 和 WorkArena++~\citep{boisvert2024workarenacompositionalplanningreasoningbased} 在 ServiceNow 中评估组合式任务完成；CRMArena~\citep{huang-etal-2025-crmarena} 与 CRMArena-Pro~\citep{huang-etal-2025-crmarena-pro} 聚焦 Salesforce 特定工作流；ITBench~\citep{jha2025itbenchevaluatingaiagents} 面向 IT 事件解决。多领域工作拓展了范围，但强调点不同：TheAgentCompany~\citep{xu2024theagentcompanybenchmarkingllmagents} 模拟一家初创软件公司，要求智能体通过 Web 浏览器、bash 终端和代码执行交互，这一范式与 \ours{} 的结构化工具调用 API 场景根本不同；WorkBench~\citep{styles2024workbenchbenchmarkdatasetagents} 覆盖办公生产力工具；EnterpriseBench~\citep{vishwakarma2025llmshelpworksandbox} 则评估沙箱企业数据上的函数调用。在这些基准中，关系数据库复杂度一贯受限于不足 25 张表；任务要么局限于单一厂商生态，要么缺少专家编写的依据，或未明确评估拒绝行为。\ours{} 跨越八个企业领域，既包含业务系统（CSM、ITSM、HR），也包含协作服务（Email、Calendar、Teams、Drive），并提供高连接度的 164 张数据库表、512 个工具、1,150 个专家策划任务以及受策略约束的不可行场景。

\paragraph{智能体规划与计算机使用}
规划是自治智能体的核心能力，已有若干基准在多样的通用场景中研究它。UserBench~\citep{qian2025userbenchinteractivegymenvironment} 在多轮旅行规划任务上评估智能体，其中模拟用户逐步且隐式地表达偏好，因此需要主动澄清意图。Gaia2~\citep{froger2025arescalingagentenvironments} 在异步模拟移动环境中评估智能体，测试搜索、执行、时序推理、适应性、歧义处理和多智能体协作。VitaBench~\citep{he2025vitabenchbenchmarkingllmagents} 在送餐、到店就餐和在线旅行等真实服务的复杂多轮任务上评估智能体，并使用具有动态偏好的模拟用户。另一条并行研究线关注计算机使用智能体：OSWorld~\citep{xie2024osworld}、WindowsAgentArena~\citep{bonatti2024arena}、WebArena~\citep{zhou2024webarenarealisticwebenvironment} 和 UI-Vision~\citep{nayak2025uivisiondesktopcentricguibenchmark} 都在需要复杂序列决策的桌面或 Web GUI 上评测智能体。尽管这些设置也要求精密的规划，它们处理的是日常情景或计算环境，而非企业环境中受策略管控的多系统语境。\ours{} 同样强调较长的规划跨度，但其独特位置在于规划深度与企业领域保真度的交汇处。
