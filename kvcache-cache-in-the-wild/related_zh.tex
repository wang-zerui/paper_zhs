\section{相关工作}
\label{sec:related}

\nospacestitle{通过 {\kvcache} 缓存跨请求复用 {\kvcache}。}
利用 {\kvcache} 复用加速 LLM 服务已得到广泛研究~\cite{vllm,chunkattention,cachedattention,promptcache,sglang,cacheblend}，并已用于商业 LLM 服务~\cite{openaiapi,genimiapi,claudeapi,mooncake}。目前生产系统仅把前缀匹配视为缓存命中~\cite{chunkattention,sglang,cachedattention,openaiapi,genimiapi,claudeapi,mooncake}，因为这样可以保持原始模型推理算法不变，不损失准确率。一些研究~\cite{promptcache,cacheblend,hu2024epic} 探索了非前缀 {\kvcache} 缓存方法；待这些方法成熟并部署到生产环境后，可以重新审视本文的特征刻画。

\stitle{其他 {\kvcache} 相关优化。}
新近工作~\cite{streamingllm,h2o,infinigen,pyramidkv} 提出了运行时 {\kvcache} 压缩与删除方法，以减小 {\kvcache} 大小。StreamingLLM~\cite{streamingllm} 仅保留由最近 token 与少量初始 token 组成的有限注意力窗口。H2O~\cite{h2o} 推理时只纳入对注意力分数贡献最大的 token。InfiniGen~\cite{infinigen} 推测性地选择对注意力分数至关重要的 token，并丢弃其余 token。KVQuant~\cite{KVQuant} 以很小的困惑度损失实现 3-bit KV 缓存量化，使大语言模型能够快速进行百万长度上下文推理。这些方法降低了单请求所需的 {\kvcache}，但会带来准确率下降。本文研究与这些工作兼容：如果未压缩、完整的 {\kvcache} 可以复用，那么其压缩或删减版本也同样可以复用。

\stitle{缓存策略优化。}
缓存优化长期以来一直是研究重点，包括通用缓存策略~\cite{lruk,slru,twoq,eelru,lrfu,lirs,arc,mq,car,clockpro,DBLP:journals/tos/EinzigerEFM22,lhd,cacheus,sieve,cherkasova1998improving} 与特定领域缓存~\cite{yang2020twemcache,berg2020cachelib,icebreaker,fasscache}。本文延续这一研究方向，利用所刻画的 {\kvcache} 复用性质优化 {\kvcache} 缓存策略。

\stitle{LLM 服务优化。}
本文延续提升 LLM 服务系统性能的研究~\cite{DBLP:conf/osdi/ZhongLCHZL0024,DBLP:journals/corr/abs-2404-09526,DBLP:conf/sosp/KwonLZ0ZY0ZS23,alpaserve,DBLP:conf/osdi/YuJKKC22,DBLP:conf/isca/PatelCZSGMB24,cachedattention,DBLP:journals/corr/abs-2412-17246}，重点刻画面向 {\kvcache} 缓存的服务工作负载。本文工作与 {\kvcache} 缓存以外的其他优化彼此正交。
