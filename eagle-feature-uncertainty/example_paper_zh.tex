\begin{abstract}
自回归解码使得大型语言模型 (LLM) 的推理非常耗时。在本文中，我们重新考虑推测性抽样并得出两个关键观察结果。首先，特征（第二层到顶层）级别的自回归比令牌级别更直接。其次，特征（第二层到顶层）级别的自回归固有的不确定性限制了其性能。基于这些见解，我们引入了 EAGLE（提高语言模型效率的外推算法），这是一个简单但高效的推测采样框架。通过合并一个时间步长的令牌序列，EAGLE 有效地解决了不确定性，以最小的开销实现精确的第二层到顶层特征预测。我们对 EAGLE 进行了全面评估，包括 Vicuna 和 LLaMA2-Chat 系列的所有模型、MoE 模型 Mixtral 8x7B Instruct 以及对话、代码生成、数学推理和指令跟踪等任务。对于 LLaMA2-Chat 70B，EAGLE 实现了\textbf{2.7倍-3.5倍}的延迟加速比，吞吐量加倍，同时保持了生成文本的分布。
\end{abstract}



\section{介绍}



自回归解码是大型语言模型 (LLM) 的事实上的标准，它按顺序生成令牌，导致生成缓慢且成本高昂。 
基于投机抽样 \cite{leviathan2023fast,chen2023accelerating} 的方法通过将流程分为低成本草案阶段和针对起草令牌的 \emph{并行化} 验证阶段来解决此问题，从而允许在单个 LLM 通行证中验证多个令牌。这些方法通过每次生成多个令牌来加速生成。更重要的是，验证阶段确保文本分布与原始LLM的解码结果精确对齐，保持生成内容的完整性。

应用推测性抽样取决于找到一个反映原始 LLM 功能但延迟时间较短的草稿模型，通常涉及同一 LLM 系列的较低参数版本。例如，在包含 7B、13B 和 70B 参数模型的 LLaMA2 \cite{touvron2023llama} 系列中，使用 7B 模型作为 70B 模型的草图模型是有效的，而为最小的 7B 变体找到合适的草图模型则很棘手。另一种方法是使用 TinyLLaMA \cite{zhang2024tinyllama}，但由于 LLaMA2-Chat 和 TinyLLaMA-Chat 之间的指令模板不一致，因此对于指令调整模型来说不可行。尽管 7B 模型具有作为草案模型的潜力，但其高开销削弱了加速增益。
由于成本高昂，专门为推测性抽样训练新的、大小合适的草图模型也不是理想的解决方案： 
TinyLLaMA 在 3,000B 令牌上进行训练，而 EAGLE 在 2-4B 令牌上进行训练。



增强投机采样加速的关键在于减少时间开销，提高原LLM的稿件接受率~\cite{chen2023cascade,xia2023speculative,santilli-etal-2023-accelerating}。许多方法都致力于减少起草阶段的开销。 Lookahead \cite{fu2023lookahead} 采用 n-gram 和 Jacobi 迭代，而 Medusa \cite{medusa} 使用一组 MLP，根据原始 LLM 的第二层到顶层特征来预测标记。这些策略显着减少了生成草稿的延迟，从而提高了加速速度。然而，它们的有效性受到所生成草稿的较低准确度的限制，Medusa 的准确度约为 0.6，而 Lookahead 的准确度甚至更低。相比之下，我们的方法的准确度约为 0.8。

为了克服这些限制，我们引入了 EAGLE（提高语言模型效率的外推算法），这是一种有效的推测采样方法，基于以下两个观察结果。


\textbf{首先，特征级别的自回归比标记级别的自回归更简单。} 在本文中，“特征”指的是原始LLM的第二层特征，位于LM头之前。
与自然语言的简单转换的标记序列相比，特征序列表现出更多的规律性。在特征级别进行自回归处理，然后使用原始 LLM 的 LM 头导出标记，比直接自回归预测标记产生更好的结果。如图 \ref{fig:ob12} 所示，自回归预测特征可产生更好的性能，这通过 1.9 倍的加速比（相比 1.5 倍）更高来证明。 

\textbf{其次，采样过程中固有的不确定性极大地限制了预测下一个特征的性能。}
在文本生成中，目标 LLM 相应地预测标记和样本的分布，从而引入随机性。特征是高维且连续的，不能以类似的方式处理。如图\ref{fig:random}所示，对“am”或“always”等不同标记进行采样会产生不同的特征序列，从而在特征级自回归中引入歧义。 Medusa 在预测间隔标记时面临类似的问题，不确定输入$f_I$的真实目标应该是$p_{am}$还是$p_{always}$。为了解决这个问题，EAGLE 将提前一个时间步的标记序列（包括采样结果）输入到草稿模型中。在图\ref{fig:random}所示的示例中，这涉及基于$f_{I}$和$t_{always}$预测$f_{always}$，以及基于$f_{I}$和$t_{am}$预测$f_{am}$。如图\ref{fig:ob12}所示，通过解决不确定性，加速比进一步从1.9倍提高到2.8倍。

我们分别使用 MT-bench、HumanEval、GSM8K 和 Alpaca 数据集进行了对话、代码生成、数学推理和指令跟踪任务的实验。测试的法学硕士包括 Vicuna 和 LLaMA2-Chat 系列的所有模型，以及 Mixtral 8x7B Instruct。对于 LLaMA2-Chat 70B，EAGLE 实现了\textbf{2.7倍-3.5倍}的加速比，吞吐量翻倍，理论上保证了生成文本分布的保留。
图\ref{mt-t0}和\ref{mt-t1}说明了EAGLE在MT-bench\cite{zheng2023judging}上的性能，MT-bench是一个高度真实的基准，模拟实际应用程序和真实场景，包括类似于与ChatGPT对话的多轮指令。我们选择使用这个基准，因为它已被当前最先进的技术（包括 Lookahead 和 Medusa）所采用，以展示它们的加速比。这种选择有助于我们的方法和这些方法之间进行公平和直接的比较。与最近提出的基于推测采样的框架 Lookahead 和 Medusa 相比，EAGLE 分别实现了 \textbf{1.7倍-2.1倍} 和 \textbf{1.5倍-1.6倍} 加速。 
EAGLE 与其他加速或吞吐量提高方法并行运行，例如量化、编译等。将 EAGLE 与这些技术相结合可以进一步降低 LLM 系统的运营成本。例如，借助 gpt-fast \cite{gptfast}，EAGLE 在单个 RTX 3090 GPU 上将 LLaMA2-Chat 7B 解码加速至 160.4 个令牌/秒。

EAGLE 拥有较低的培训成本。对于 LLaMA2-Chat 70B 模型，EAGLE 使用 ShareGPT 数据集中不超过 70k 的对话来训练参数少于 1B 的解码器层。训练在 4x A100 (40G) GPU 上于 1-2 天内完成。 EAGLE 在 7B、13B 和 33B 模型上的训练甚至可以在 RTX 3090 节点上进行 1-2 天的训练。在实际应用中，EAGLE 只需要一次训练即可为每个查询提供加速。随着查询数量的增加，EAGLE 的摊销训练成本变得可以忽略不计。




除了性能之外，EAGLE 还具有其他优势：
\begin{itemize}
 \item \textbf{概论：} EAGLE 适用于任何自回归法学硕士（至少原则上）。我们已在 MT-bench、GSM8K、HumanEval 和 alpaca 数据集上以零样本方式将 EAGLE 应用于 LLaMA2-Chat (7B、13B、70B)、Vicuna (7B、13B、33B) 和 Mixtral 8x7B Instruct。
 EAGLE 遵循 LLM 社区中常用的零样本/少样本设置。所有实验均采用相同的权重，仅在 ShareGPT 数据集上进行训练，无需对评估数据集进行任何额外训练。该方法仅向LLM添加一个轻量级插件（单个变压器解码器层），可以轻松部署在生产环境中。 
 \item \textbf{可靠性：} EAGLE 不涉及对原始 LLM 的任何微调，理论上保证无论是贪婪还是非贪婪设置，EAGLE 都能保留输出分布。 
 这与 Lookahead 和 Medusa 形成鲜明对比，它们要么只关注贪婪设置，要么不保证在这些设置中保留分布。
 
\end{itemize}




\section{预赛}


\textbf{注释。} 在本文中，“目标LLM”表示旨在加速的LLM，而“草案模型”是指用于草案生成的模型。 “特征”通常表示 LLM 的第二层特征，即 LM 头之前的隐藏状态。令牌用小写$t$表示，它们的嵌入用$e$表示，特征用$f$表示，分布用$p$表示。序列以大写字母表示，例如，$T_{i:j}$ 代表$(t_i,t_{i+1},\ldots,t_{j})$。在 LLM 中，输入$T_{1:j}$通过嵌入层转换为嵌入$E_{1:j}$，然后转换为特征$F_{1:j}$，LM Head 将$f_{j}$映射到分布$p_{j+1}=\text{LM\_Head}(f_{j})$，对下一个标记$t_{j+1}$进行采样。对于任何整数 $j\ge 1$，令牌级别的普通自回归由 $T_{1:j}\rightarrow E_{1:j}\rightarrow f_j\rightarrow p_{j+1}\rightarrow t_{j+1}$ 描述。

\textbf{推测性抽样。} 
推测抽样通过草稿和验证阶段进行，草稿阶段使用较小的模型来生成$\gamma$代币$\hat{T}_{j+1:j+\gamma}$及其分布$\hat{P}_{j+1:j+\gamma}$。在验证阶段，目标 LLM 的单次前向传递会产生概率$P_{j+1:j+\gamma}$。然后按顺序评估令牌，令牌$\hat{t}_{j+i}$的接受概率为$\min(1,p_{j+i}(\hat{t}_{j+i})/\hat{p}_{j+i}(\hat{t}_{j+i}))$。在拒绝令牌$\hat{t}_{j+i}$后，所有后续令牌都将被丢弃，并且该令牌将根据分布$\text{norm}(\max(0,p_{j+i}-\hat{p}_{j+i}))$重新采样。正如推测性抽样\cite{leviathan2023fast}附录 A.1 中所证明的，该方法相当于直接从目标 LLM 抽样。 EAGLE采用这种方法，确保\textbf{对于贪婪和非贪婪设置，生成文本的分布保持不变}。


\section{鹰}

EAGLE 与其他基于推测抽样的方法保持一致，包含起草阶段和验证阶段。



\subsection{起草阶段}
\label{me:draft}


EAGLE 与其他方法的主要区别主要在于起草阶段。
图\ref{comparation}说明了不同方法的起草阶段的示意图。推测性采样\cite{leviathan2023fast,chen2023accelerating}和前瞻\cite{fu2023lookahead}根据标记预测标记。 Medusa~\cite{medusa}使用目标LLM的特征$f_2$独立预测$t_4$和$t_5$。 EAGLE 使用特征序列 $(f_1,f_2)$ 和标记序列 $(t_2,t_3)$ 预测$f_3$，并提前一个时间步长。从$p_4=\text{LM Head}(f_3)$开始，对$t_4$进行采样。随后，将$f_3$和$t_4$连接到输入序列中以预测下一个特征$f_4$并对后续标记$t_5$进行采样。

Speculative Sampling and Lookahead predict tokens based on tokens, Medusa predicts tokens based on features, whereas EAGLE uniquely predicts features based on both features and tokens.

如图\ref{pipline}所示，EAGLE的草稿模型包括三个模块：Embedding层、LM Head和Autoregression Head。 Embedding 层和 LM Head 使用目标 LLM 的参数，不需要额外的训练。草稿模型将形状的特征序列（bs，seq\_len，hidden\_dim）和形状的高级标记序列（bs，seq\_len）作为输入。然后，它将标记序列转换为形状 (bs, seq\_len, hide\_dim) 的标记嵌入序列，并将其连接起来形成形状 (bs, seq\_len, 2$\times$hidden\_dim) 的融合序列。自回归头由 FC 层和解码器层组成。
FC层将融合序列的维度降低到(bs, seq\_len,hidden\_dim)，然后我们利用解码器层来预测下一个特征。 LM Head 根据特征计算分布，并从中采样下一个标记。最后，将预测特征和采样标记连接到输入中，促进自回归过程的继续。 
EAGLE 使用树注意力创建树形结构草稿，通过 $m$ 前向传递生成深度为 $m$ 且超过 $m$ 标记的草稿树。例如，如图\ref{pipline}所示，EAGLE 仅用 3 次前向传递就起草了一个 10 个令牌树。
EAGLE 使用的实际树结构详见附录\ref{ap:tree}。

\subsection{草稿模型的训练}

预测下一个特征构成了一个回归任务，为此我们采用 Smooth L1 损失（见图 \ref{comparation} EAGLE）：
\begin{equation*}
 L_{reg} = \text{Smooth L1}(f_{i+1}, \text{Draft\_Model}(T_{2:i+1}, F_{1:i}))。
\end{equation*} 
预测特征是草案模型的中间目标，最终目标是预测标记以生成标记序列。因此，我们还利用分类损失来直接优化最终目标：
\begin{gather*}
    {p}_{i+2}=\text{Softmax}(\text{LM\_Head}({f}_{i+1})), \\
    \hat{p}_{i+2}=\text{Softmax}(\text{LM\_Head}(\hat{f}_{i+1})), \\
 L_{cls} = \text{Cross\_Entropy}({p}_{i+2},\hat{p}_{i+2})。
\end{gather*}
通过整合回归损失和分类损失，我们使用组合损失函数$L=L_{reg}+w_{cls}L_{cls}$训练自回归头。
通常，分类损失在数值上比回归损失大一个数量级。因此，我们将 $w_{cls}$ 设置为 0.1。

EAGLE 的自回归头理想地使用目标 LLM 的自回归生成的文本进行训练，但这种方法成本高昂。幸运的是，EAGLE 对训练数据表现出较低的敏感性（第\ref{sec:abadata}节中的消融研究）。我们没有使用目标法学硕士生成的文本，而是使用固定的数据集，从而大大减少了开销。 
在绘图阶段，EAGLE 自回归处理特征。特征的不准确可能会导致错误累积。为了缓解这个问题，我们通过在训练过程中将从均匀分布$\mathcal{U}(-0.1, 0.1)$采样的随机噪声添加到目标LLM的特征〜\cite{jain2023neftune}来采用数据增强。



\subsection{验证阶段}
利用树注意力，目标 LLM 通过一次前向传递计算树结构草案中每个标记的概率。在草稿树的每个节点，我们递归地应用推测采样算法来采样或调整分布（详细信息参见附录\ref{ap:mss}），与SpecInfer\cite{miao2023specinfer}一致，确保输出文本的分布与目标LLM的分布一致。同时，我们记录已接受的令牌及其功能，以便在下一个起草阶段使用。

\section{实验}


\textbf{模型和任务。} 我们对 Vicuna 模型（7B、13B、33B）、LLaMA2-chat 模型（7B、13B、70B）和 Mixtral 8x7B Instruct 进行了实验，涵盖了当前主流 LLM 的常见尺寸。
我们分别使用 MT-bench \cite{zheng2023judging}、HumanEval \cite{chen2021evaluating}、GSM8K \cite{cobbe2021training} 和 Alpaca \cite{alpaca} 数据集对 EAGLE 进行了多项任务评估，包括多轮对话、代码生成、数学推理和指令跟踪。
推测抽样\cite{leviathan2023fast}以批量大小 1 进行实验，该设置随后被 DistillSpec \cite{zhou2023distillspec} 和 BiLD \cite{kim2023speculative} 等其他作品采用。同样，我们的大部分实验也采用了这种设置。第 \ref{sec:bsne1} 节介绍了批量大小大于 1 的实验。

\textbf{指标。}
与其他基于推测采样的方法一样，EAGLE 主要关注延迟而不是吞吐量。我们使用以下指标评估加速效果：
\begin{itemize}
 \item Walltime 加速比：相对于普通自回归解码的实际测试加速比。
  \item 平均接受长度$\tau$：目标LLM每次前向传递接受的平均令牌数。
 \item 接受率$\alpha$：起草过程中接受的令牌与生成的令牌的比率，衡量起草的准确性。它不太适用于树草稿，因为每个位置采样了多个令牌，但只接受了一个。因此，在测量这个指标时，\textbf{我们利用链草稿而不需要树关注}，与推测采样和 DistillSpec 保持一致。 EAGLE 的草稿模型输入特征和标记序列。自回归特征处理可能会传播错误，因此我们将接受率测量为$n\text{-}\alpha$，考虑到草稿模型预测的$n$特征，可能不准确。
\end{itemize}

EAGLE 的加速理论上保证了目标 LLM 输出分布的保留。因此，评估 EAGLE 生成结果的质量既没有必要，也没有意义。

\textbf{训练。}
我们确定了法学硕士目标。 EAGLE 在 ShareGPT 数据集上进行训练，使用 68,000 次对话迭代，学习率设置为 3e-5。我们采用 AdamW 优化器，将 beta 值$(\beta_1, \beta_2)$ 设置为 (0.9, 0.95)，并实现 0.5 的梯度裁剪。 
7B、13B、33B、70B模型对应的EAGLE可训练参数分别为0.24B、0.37B、0.56B、0.99B。 MoE 模型 Mixtral 8x7B 的 EAGLE 可训练参数为 0.28B。 EAGLE的特点是训练成本低；对于 70B 模型，自回归头可在 1-2 天内在 A100 40G 服务器上进行训练。

\subsubsection{草图模型的输入}
\label{sec:input}
与其他基于推测抽样的方法相比，EAGLE 的关键创新在于它利用了目标 LLM 计算的特征，并将抽样结果纳入草稿模型的输入以解决随机性问题。我们对 Vicuna 7B 进行了消融研究，评估了具有不同输入的草案模型。我们测试了四种类型的输入：feature\&shifted-token (EAGLE)、feature\&unshifted-token、token 和 feature。 feature\&shifted-token (EAGLE) 和 feature\&unshifted-token 都集成了不同级别的语义信息。区别在于，特征转移令牌（EAGLE）输入提前一步的令牌，使其能够有效地解决随机性问题。除了使用 FC 层来降低特征\&令牌输入的维度之外，草稿模型的结构保持完全一致。图\ref{fig:aba-input}展示了以Vicuna 7B为目标LLM的MT平台上的实验结果。可以得出三个观察结果。
\begin{itemize}
 \item 首先，当草稿模型的参数数量有限时，利用特征会产生比令牌稍好的结果。
 \item 其次，合并特征和令牌会适度提高性能，主要是因为离散、无错误的令牌减轻了特征错误累积，从特征\&未移动令牌和仅特征草稿模型的类似$0\text{-}\alpha$可以明显看出，并且显着改进了$1\text{-}\alpha$。
 \item 第三，解决抽样过程中固有的随机性会带来最显着的改进。与 feature\&unshifted-token 相比，feature\&shifted-token 方案不会增加复杂性，但通过简单地将令牌推进一个时间步长，显着增强了草稿模型的能力，从而允许草稿模型考虑采样的随机性。
\end{itemize}

\subsection{批量大小和吞吐量}
\label{sec:bsne1}

LLM 中的推理受内存限制\cite{patterson2004latency,shazeer2019fast}，导致 GPU 计算资源未得到充分利用。基于推测采样的方法提高生成速度的原理在于更有效地利用 GPU 计算资源。随着批量大小的增加，GPU的可用计算能力会减少，导致加速效果降低。在本节中，我们将展示批量大小超过 1 的场景的实验结果。如表\ref{tab:bs}所示，加速比随着批量大小的增加而减小。当使用 Vicuna 7B 作为目标 LLM 时，bs=4 时的加速比高于 bs=3 时的加速比。这是因为，在 EAGLE 的验证阶段，目标 LLM 在一次前向传递中处理多个令牌，并且 bs=4 时的处理速度比 bs=3 时更快。相比之下，在目标 LLM 每次前向传递处理一个令牌的普通自回归解码中，bs=3 和 bs=4 时的速度几乎相同。

尽管基于推测采样的方法主要关注延迟，但我们还研究了 EAGLE 批量大小$>1$的吞吐量，这是 LLM 系统的另一个关键指标。与普通自回归解码相比，EAGLE 需要稍多的 CUDA 内存。对于作为目标 LLM 的 Vicuna 7B，在具有 24G CUDA 内存的单个 RTX 3090 的内存约束下运行，普通自回归解码和 EAGLE 的最大批量大小 (bs) 分别为 8 和 7。在 LLaMA2-Chat 70B 的情况下，受 4 个 A100 (40G) GPU 总计 160G CUDA 内存的限制，普通自回归解码和 EAGLE 的最大 bs 分别为 5 和 4。所有评估均以 FP16 精度进行。我们计算了不同bs的吞吐量并选择了最大值。普通自回归解码和 EAGLE 都在各自的最大 bs 下实现了最大吞吐量。树注意力消耗更多的计算资源。当bs=7时，计算资源不太丰富，使得不使用树注意力更加有利。如表\ref{tab:bs}所示，EAGLE 的吞吐量提高了 2 倍。

\section{相关工作}

人们对加速语言模型进行了大量研究，涉及蒸馏\cite{hinton2015distilling}、量化\cite{hubara2018quantized,shen2020q,kim2021bert,zadeh2020gobo,zafrir2019q8bert}、剪枝\cite{gale2019state,sanh2020movement,kurtic2022optimal,voita2019analyzing}和创新网络架构设计\cite{gu2023mamba,wu2020lite}等技术。这些方法旨在减少每次前向传递的延迟。

与我们的方法类似的是基于推测抽样的框架。早期的作品\cite{stern2018blockwise,sun2021instantaneous}加速了贪婪解码，而推测采样\cite{leviathan2023fast,chen2023accelerating}将其扩展到非贪婪采样，可证明保持了原始输出分布。确保输出分布不变使得加速更具挑战性；许多研究都探讨了有损加速作为一种权衡。例如，DistillSpec \cite{zhou2023distillspec} 使用宽大函数修改接受概率，BiLD \cite{kim2023speculative} 如果与目标 LLM 分布的距离度量低于特定阈值则接受草稿，而 Medusa \cite{medusa} 使用硬阈值和熵相关阈值的最小值进行截断。相比之下，EAGLE 不采用任何松弛，并保持 LLM 的输出分布不变。

基于推测抽样的方法之间的主要差异主要体现在起草阶段。推测性抽样\cite{leviathan2023fast,chen2023accelerating}利用目标 LLM 的较低参数版本作为草稿模型。自推测解码 \cite{zhang2023draft} 在草稿生成期间跳过目标 LLM 的某些层。 SpecInfer \cite{miao2023specinfer} 采用一组小模型来并行生成草稿。级联推测性起草\cite{chen2023cascade}和分阶段推测性解码\cite{spector2023accelerating}级联不同的开销草案模型。 
在线推测解码\cite{liu2023online}根据查询分布训练草稿模型。
Medusa \cite{medusa}等方法\cite{hooper2023speed,fu2023lookahead,yang2023predictive}不采用单独的目标LLM；相反，他们利用目标法学硕士的特征或权重来生成草稿。 REST \cite{he2023rest} 根据检索方法生成草稿。
LLMA \cite{yang2023inference}，用于输入和输出重叠的语法纠正等任务，直接从输入中检索草稿。 



\section{结论}
在本文中，我们介绍了 EAGLE，一种高效的推测采样框架。 EAGLE 在更结构化（第二层到顶层）特征级别上自回归地执行起草过程，并通过合并前面一个时间步的标记来减轻预测下一个特征时的采样不确定性。 EAGLE 保证保留 LLM 的输出分布，同时显着提高生成速度。在 MT-bench 上，EAGLE 比普通自回归解码快 2.1 倍到 3.8 倍，比 Lookahead 快 1.7 倍到 2.1 倍，比 Medusa 快 1.5 倍到 1.6 倍。

\subsection{树结构}
\label{ap:tree}
利用树注意力，EAGLE 生成树结构草案。图\ref{fig:tree}的左侧说明了草稿的树结构，而右侧则描述了不使用树注意力时相应的链结构草稿（如第\ref{sec:abtree}节中详细介绍的消融研究中所使用的）。在贪婪设置中，我们选择概率最高的前 $k$ 标记作为子节点。在非贪婪设置中，我们对 $k$ 令牌进行采样。子节点的数量$k$可以从图9中推断出来；例如，根节点处的$k=4$。 
无论采用树形结构还是链式结构草图，草图模型在草图阶段都会经历 5 次前向传递。
在验证阶段，每个令牌的概率是通过目标 LLM 的单次前向传递获得的。


\textbf{为什么我们要用这样的树结构呢？} 如图 9 所示，树结构的选择并未经过严格优化，而是基于直觉：较高概率标记的分支应该更深、更宽。对于本文，所有实验中的所有模型都使用图 9 中所示的草稿结构。但是，最佳树结构可能与上下文相关。例如，随着批量大小的增加和冗余计算资源的减少，较小的树可能会更好。调整草案结构可能会提高性能。

\subsection{多轮推测采样}
\label{ap:mss}
与推测采样的链式结构草案不同，EAGLE 采用树形结构草案，需要对采样算法进行修改。推测采样的采样算法A可以简单描述为：如果接受了一个token，则返回该token；如果接受了，则返回该token；如果接受了，则返回该token。否则，它会从调整后的分布中采样一个令牌。对于具有$k$候选令牌的树形结构草案，多轮推测采样递归调用算法A。多轮推测采样不是在拒绝令牌后直接从调整后的分布中采样，而是再次调用A。如果所有令牌都被拒绝，则直接从调整后的分布中采样。算法\ref{alg:mss}中提供了多轮推测采样的伪代码。

\begin{algorithm}
   \caption{多轮推测抽样}
   \label{alg:mss}
\begin{algorithmic}
 \STATE {\bfseries 输入：} 目标分布 $p$、样本 $t_i$ 和分布 $\hat{p_i}$，每个 $i$ 从 1 到 $k$，其中 $t_i$ 是从 $\hat{p_i}$ 采样的，
 \STATE {\bfseries 输出：}样本$x \sim p$ ;
   \STATE  $i \leftarrow 1$
   \FOR {$i \leq k$}
   \STATE $r \leftarrow U(0,1)$ 
   \IF{$r<{p(t_i)}/{\hat{p_i}(t_i)}$}
\STATE {\bfseries 返回} $t_i$
   \ENDIF
   \STATE $p \leftarrow norm(max(0,p(t_i)-\hat{p_i}(t_i)))$ 
   \STATE $i \leftarrow i+1$
   \ENDFOR
\STATE 样品$t \sim p$
\STATE {\bfseries 返回} $t$
\end{algorithmic}
\end{algorithm}
