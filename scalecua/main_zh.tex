\begin{abstract}
视觉语言模型（Vision-Language Model，VLM）使能够自主操作 GUI 的计算机使用智能体（Computer Use Agent，CUA）成为可能，展现出巨大潜力。然而，要开发鲁棒的 CUA，需要大量关于软件界面和操作过程的领域内知识。不同于互联网上广泛存在的图文对，计算机使用数据，尤其是操作轨迹，不仅稀缺，而且采集成本高昂。因此，该领域的进展仍同时受制于数据规模以及现有 VLM 有限的迁移能力。

本文提出 \modelname，向扩展开源 CUA 迈出一步。作者通过一个将自动化智能体与人类专家结合起来的闭环流水线，构建了覆盖 6 种操作系统和 3 类任务领域的大规模数据集。在这些扩展后的数据上训练得到的 \modelname 能够跨平台无缝运行。具体而言，它相较基线取得显著增益（WebArena-Lite-v2 上 $+26.6$，ScreenSpot-Pro 上 $+10.7$），并刷新多项最佳结果（MMBench-GUI L1-Hard 为 $94.4\%$，OSWorld-G 为 $60.6\%$，WebArena-Lite-v2 为 $47.4\%$）。这些发现凸显了数据驱动扩展对于通用跨平台 CUA 的作用。作者发布数据、模型和代码以推动后续研究：\url{https://github.com/OpenGVLab/ScaleCUA}。
\end{abstract}

\section{引言}
人类能够通过图形用户界面（GUI）与数字环境交互，从而高效获取信息并完成任务。近期视觉语言模型的发展赋予了模型强大的视觉感知和任务规划能力，使这类交互的自动化日益可行。因此，近来的研究越来越关注计算机使用智能体，也称 GUI 智能体；其目标是仅依赖视觉观测，自主操作桌面、移动端和 Web 平台。

一些 CUA~\citep{qin2025uitars,anthropic2025claude37,hong2025glm,cua2025} 已表现出很强的性能，但它们通常建立在闭源模型或无法获得的专有数据集之上。更根本地说，有效使用计算机需要丰富的软件与操作流程领域知识，而当前基础模型在这方面仍有很大缺口。与互联网上大量存在的图文对不同，计算机使用数据，尤其是细粒度动作轨迹，数量稀少、采集昂贵、标注成本高，并且不会自然地在线归档。此外，软件、网页和操作系统快速演化，已有轨迹还面临过时风险，进一步限制了其效用。这些挑战从数据规模和模型泛化性两方面形成了扩展 CUA 的显著瓶颈。为解决这些限制，作者主要推进两项工作：（a）构建大规模、跨平台、以 GUI 为中心的训练语料；（b）开发一族可扩展、通用的基础模型，用于通用计算机使用智能体。

作者首先提出由两个协同闭环组成的\emph{跨平台交互式数据流水线}。\emph{智能体--环境交互闭环}使自动化智能体能够与多种 GUI 环境交互；\emph{智能体--人类混合数据采集闭环}则引入专家标注轨迹，以保证覆盖面与质量。该流水线覆盖 Windows、macOS、Linux、Android、iOS 和 Web 六类主要平台，能够采集丰富的屏幕状态观测、元数据（例如无障碍树、XML、DOM 结构等）以及原始轨迹。作者还设计了统一动作空间，使智能体能够更一致、更高效地与多种真实环境交互。

依托这一基础设施，作者整理并标注了一个全面的开源计算机使用训练数据集，包含三类主要任务：（a）\emph{GUI 理解}，共 47.1 万个样本，覆盖区域描述、OCR、布局理解等；（b）\emph{GUI 定位}，共 1710 万个训练样本，用于支持更精确的 UI 元素定位；（c）\emph{任务完成}，包含超过 1.5 万条弱语义轨迹和 4000 条高层目标驱动轨迹。作者使用 GPT-4o、Claude-3.7-Sonnet 等先进 VLM 标注采集到的数据，并探索数据增强以进一步提高多样性，由此建立了一个完全开放且多样的训练数据集。

在该语料之上，作者以 Qwen2.5-VL~\citep{bai2025qwen25vl} 为基础训练了一系列名为 \textbf{\modelname} 的基础智能体模型。\modelname 支持三种不同的推理范式，以提高灵活性并兼容不同智能体框架：（a）\emph{定位模式}，根据文本描述精确定位 UI 元素，便于在模块化智能体中与能力更强的推理规划器高效集成；（b）\emph{直接动作模式}，不消耗额外的中间推理 token，而是直接生成底层可执行动作，从而高效完成任务；（c）\emph{推理动作模式}，先根据当前观测和历史上下文生成思考过程，再生成下一动作，以提高任务规划准确性。数据构建阶段设计的统一动作空间使这些智能体能够通过标准化控制模式接入异构环境。

作者进行了大量实证研究，考察不同数据来源、训练任务和智能体设计等因素对性能的影响。结果表明，数据增强、弱语义轨迹和通用推理数据有助于提高规划能力。作者还在多个 GUI 智能体基准上评测不同智能体范式，并系统比较智能体式工作流与原生模型。先前研究~\citep{xu2024aguvis,qin2025uitars,cua2025,anthropic2025claude37} 也曾探索这些重要问题，但公开训练数据有限，或是在使用专有数据的封闭条件下进行；本文的研究旨在为推进基于视觉语言模型的计算机自动化提供基础性、统一的认识。

本文贡献概括如下：
\begin{enumerate}
    \item 作者通过结合自动化智能体与人类专家的交互式数据流水线，整理了一个跨平台计算机使用数据集。它覆盖 Windows、macOS、Linux、Android、iOS 和 Web 六类主要平台，以及理解、定位和任务完成三类以 GUI 为中心的任务领域，为研究和训练通用 CUA 提供了坚实基础。
    \item 作者开发了 \modelname：一族将感知、推理和动作统一在单一模型中的鲁棒基础智能体模型。它支持定位、直接动作和推理动作等灵活推理范式，并使用统一动作空间实现无缝跨平台交互。
    \item 作者在若干跨平台在线基准上，对理解、定位和端到端任务完成进行了全面评测。实验不仅表明这些智能体能够取得最佳或具有竞争力的性能，也为开发更强大的计算机使用智能体提供了有启发性的方向。
\end{enumerate}

\section{相关工作}
\label{related_work}
\textbf{视觉语言模型。}近年来，视觉语言模型取得了长足发展，既包括专有 API 服务~\citep{team2023gemini,team2024gemini,anthropic2024claude35,xai2025grok3,OpenAI2023GPT4TR,hurst2024gpt}，也包括开源模型~\citep{wang2024qwen2vl,bai2025qwen25vl,chen2024internvl,chen2024expanding,zhu2025internvl3,coreteam2025mimovltechnicalreport,team2025gemma,metaai2025llama4}，能力范围已扩展至多种任务。一些通用 VLM~\citep{team2025kimi,guo2025seed1,bai2025qwen25vl,zhu2025internvl3,coreteam2025mimovltechnicalreport,wang2025internvl35} 在预训练或监督微调阶段整合了大量 GUI 知识，因而获得了明确的计算机使用能力。然而，尽管部分工作~\citep{hurst2024gpt,anthropic2024claude35,guo2025seed1,zhu2025internvl3,bai2025qwen25vl} 在视觉语言任务上表现出较强的泛化与规划能力，它们仍难以解决简单的计算机使用任务。此外，用于训练这些模型的 GUI 语料在很大程度上仍是专有的。

\textbf{GUI 智能体。}GPT-4o 等通用 VLM 的近期进展促成了模块化 GUI 智能体：它们把决策和感知拆分为规划与定位两个角色。这类智能体通常采用\emph{规划器--定位器范式}~\citep{cheng2024seeclick,hong2024cogagent,lu2024omniparserpurevisionbased,yu2025omniparser,wu2025gui,gou2024navigating,zhang2025guimid,wu2024osatlas,zhou2025guig1}，由基于 VLM 的规划器预测下一项高层操作及相关对象描述，再由专门的 GUI 定位模型在界面中定位该对象。\citet{yang2024aria} 进一步把动作历史纳入定位，使定位器能够适应有上下文的 GUI 动态变化。

受通用\emph{智能体式工作流}~\citep{wu2023autogen,li2023camel,hong2023metagpt} 启发，一些工作~\citep{wu2024copilot,liu2025pc,zhao2025cola,Agent-S2,chen2025map} 通过协调负责规划、反思和记忆增强决策的多个智能体，将这种设计扩展到 GUI 环境。尽管性能强劲，智能体式工作流通常具有较高的计算延迟和显著的 token 消耗，而且其性能从根本上受底层 VLM 能力约束。与模块化智能体不同，\emph{原生计算机使用智能体}~\citep{xu2024aguvis,wu2024osatlas,sun2024osgenesis,qin2025uitars,luo2025gui,liu2025infigui,sun2025scienceboard} 在一个端到端训练的统一模型中整合规划与定位，并从原始视觉输入直接预测底层可执行动作。例如，AGUVIS~\citep{xu2024aguvis} 和 UI-TARS~\citep{qin2025uitars} 使用大量任务轨迹训练，表现出出色的推理与适应能力。总体而言，原生智能体使感知与动作之间的对齐更紧密；模块化智能体和智能体式工作流也能受益于原生智能体的改进。本文不仅关注跨平台 GUI 智能体基础模型的训练，还承诺开源全部数据，以加速整个领域的发展。

\textbf{GUI 数据集。}开源数据集通过捕获跨平台的多种交互、视觉感知与指令遵循行为，显著推动了 GUI 智能体的发展。在\emph{移动端}环境中，RICO~\citep{deka2017rico} 提供超过 7 万张带手势轨迹的 Android UI 屏幕；AITW~\citep{rawles2023androidinthewild} 提供约 71.5 万条与 3 万条自然语言命令对齐的人类示范；AitZ~\citep{zhang2024aitz} 则构建了 18,643 个屏幕--动作对，并附带动作思维链标注。

在 \emph{Web} 领域，MiniWoB~\citep{Tianlin2017miniwob} 模拟了多种带交互序列和奖励的 Web 任务；WebShop~\citep{shunyu2022webshop} 在真实商品目录上提供语言驱动的电子商务任务及人类轨迹；Mind2Web~\citep{deng2023mind2web} 将该思路扩展至 137 个真实网站，提供 2350 个长程开放式任务。在桌面平台方面，\citet{xie2024osworld} 构建了通过界面分解合成的 400 万样本数据集，提高了定位准确率；\citet{he2025efficientagenttrainingcomputer} 采集了 312 条人类标注轨迹，并通过轨迹增强扩充数据。

此外，一些工作探索可扩展的数据生成方式。例如，OS-Genesis~\citep{sun2024osgenesis} 通过探索合成移动端和 Web 轨迹，AGUVIS~\citep{xu2024aguvis} 则从异构开源语料中整理出带多模态定位与推理标注的大规模数据集。由于 GUI 交互轨迹的获取成本很高，另一些研究收集 GUI 教程数据以缓解数据稀缺：META-GUI~\citep{sun2022meta} 在教程中提出基于对话的标注；TongUI~\citep{zhang2025tongui} 从 YouTube、WikiHow 等教学来源收集约 14.3 万条任务轨迹，并将指令与屏幕截图、动作关联起来；GUI-World~\citep{chen2024guiworld} 提供超过 1.2 万段 GUI 屏幕录制视频，以促进对 GUI 动态的时间理解。尽管已有这些进展，现有 GUI 语料在覆盖面与多样性上仍然有限，桌面环境尤其如此。数据稀缺对 UI 元素定位和多步任务规划提出了显著挑战。

\section{跨平台交互式数据流水线}
\label{sec:data_pipeline}
开发鲁棒计算机使用智能体的一项关键挑战，是计算机使用领域缺少兼具高质量和多样性的训练数据。采集计算机使用轨迹尤其昂贵且低效，主要原因是环境具有动态性，并经常依赖特定任务的资源文件，这严重限制了全自动数据采集流水线的可行性。本节详细介绍用于训练计算机使用智能体的数据获取与标注流水线。

\subsection{概述}
\begin{figure}[t]
    \centering
    \includegraphics[width=0.9\linewidth]{figures/data_pipeline.pdf}
    \caption{\textbf{跨平台交互式数据流水线。}流水线包含两个协同闭环：（1）\textbf{智能体--环境交互闭环}，智能体通过观测与动作同桌面、移动端和 Web 等多平台 GUI 环境交互；（2）\textbf{智能体--人类混合数据采集闭环}，自主智能体与人类专家共同采集由屏幕截图和结构化元数据组成的原始轨迹。所得轨迹随后被标注并转化为 GUI 理解、GUI 定位和序列动作建模等任务的训练语料。}
    \label{fig:data_pipeline}
\end{figure}

计算机使用领域的现有数据集主要分为两类：人工轨迹采集和基于自动搜索的探索。人工采集~\citep{zhang2024aitz,rawles2023androidinthewild,deng2023mind2web,lu2024gui_odyssey} 虽然能产生高质量轨迹，却成本极高、劳动密集，而且天然难以扩展。相反，自动探索方法~\citep{sun2024osgenesis} 虽可扩展，却会产生噪声很大的轨迹。因此，任何一种策略都无法单独提供训练通用 GUI 智能体所需的质量与多样性。

基于这些限制，作者提出\emph{跨平台交互式数据流水线}，有策略地把智能体与人类整合到数据采集中。如图~\ref{fig:data_pipeline} 所示，流水线运行两个协同闭环：智能体--环境交互闭环和智能体--人类混合数据采集闭环。前者让智能体与多平台 GUI 环境交互，后者则整合由自主智能体和人类专家共同采集的轨迹。这些由屏幕截图和结构化元数据组成的轨迹随后被标注，并转化为 GUI 理解、定位和序列动作建模等任务的训练语料。双闭环框架在保持数据质量的同时保证对 GUI 状态的广泛覆盖，为训练可泛化的计算机使用智能体奠定坚实基础。

\textbf{智能体--环境交互闭环。}作者首先在 Windows、Ubuntu、macOS、Web 浏览器、Android 和 iOS 等异构平台之间建立统一接口，以标准化观测获取和动作执行。这一统一抽象支持闭环数据采集，并提供可兼容不同智能体架构的灵活接口，从而显著提高在线评测的可扩展性和效率。为构建双模式数据采集框架，作者研究了针对各平台提取 GUI 元数据的方法。对于桌面环境（Windows、Ubuntu、macOS），一般可以通过无障碍树获得界面布局和 UI 元素坐标；Web 平台通过浏览器渲染的文档对象模型（DOM）结构提供元素信息；Android 应用则可从解析后的 XML 布局文件中取得 UI 元素位置。

然而，作者观察到桌面平台的无障碍树经常缺失属性，而 iOS/iPadOS 系统限制对布局信息的访问。在这些情况下，作者使用 OmniParser~\citep{yu2025omniparser} 估计 UI 元素边界框，在噪声容忍度与效率收益之间取得平衡。

\textbf{智能体--人类混合数据采集闭环。}在统一多种环境的交互接口之后，下一个自然问题是如何部署自动智能体来收集交互轨迹，同时最大限度覆盖 GUI 状态。作者实验了两种不同的探索策略。第一种使用 GPT-4o、Claude、Gemini 等 VLM 驱动的智能体浏览界面；但由于这些模型的内在偏置，所得轨迹缺少足够多样性。第二种策略使用规则驱动的随机游走智能体。规则智能体采用深度优先搜索（DFS）进行探索，每一步都从可用动作空间中随机选择一个动作，并用启发式剪枝减少搜索中的冗余或无信息分支。该策略的详细设计见附录中的数据整理细节。去重后，这一简单方法实现了明显更广的 GUI 覆盖。虽然所得轨迹在宏观层面往往缺少明确高层目标，但其中许多子序列仍能为智能体模型学习提供有价值的监督信号。

尽管自动化提高了效率，大量质量评估仍揭示出系统元数据和基于视觉预测的边界框中存在相当多噪声。因此，为降低噪声并保证高质量标注，作者用专家整理的轨迹补充自动采集。为简化专家操作，作者构建了一个统一的跨平台数据采集系统，将前端交互界面与后端环境解耦，使标注人员能够高效切换平台。专家需要完成生产力、娱乐和系统操作等领域的特定目标。

结合智能体驱动与专家驱动两种方式，作者得到规模可观的原始 GUI 轨迹语料，其中包含大量屏幕截图及相应元数据。随后，作者使用 GPT-4o~\citep{hurst2024gpt}、Claude-3.5~\citep{anthropic2024claude35} 等先进 VLM 进行数据标注，并将语料划分为 GUI 理解、GUI 定位和任务完成三类主要任务。这个全面的数据集最终为训练可泛化的计算机使用智能体提供了坚实基础。

\textbf{统一动作空间。}如附录动作空间表所示，作者建立了覆盖桌面、浏览器和移动端三类主要环境的跨平台动作空间。这一统一接口支持一致的行为建模，并便于在异构平台上共同训练。动作空间既包含通用操作的核心子集（如 \texttt{click}、\texttt{write} 等），也包含移动环境所需的特定平台动作（如 \texttt{long\_press}、\texttt{open\_app} 等）。统一动作空间使智能体能够泛化核心行为，同时保留利用环境特定动作的灵活性。由于每项动作都以感知平台但语义一致的方式表达，该设计还简化了数据标注和下游策略学习；更多细节见原文附录的动作空间小节。

\section{扩展计算机使用智能体}
\label{sec:method}

\subsection{任务定义}
CUA 已被用于程序化自动操作。早期方法如利用 DOM 解析完成 Web 自动化的 Selenium\footnote{\url{https://github.com/SeleniumHQ/selenium}}，以及编写确定性桌面交互脚本的 AutoHotkey\footnote{\url{https://github.com/AutoHotkey/AutoHotkey}}，实现了精确但受限的界面控制。大规模 VLM 极大拓宽了这一范式，使智能体~\citep{cheng2024seeclick,wang2024mobile,zhang2025appagent} 能够在图形用户界面上进行像素级感知与交互。

时刻 $t$ 的智能体--环境交互可以简单定义为：
\begin{equation}
a_t = \pi_{\theta}(task, o_t, h_{<t}), \quad o_{t+1} = \mathcal{E}(a_t),
\end{equation}
其中，$\pi$ 表示参数为 $\theta$ 的智能体模型，$\mathcal{E}$ 表示虚拟机或 Docker 容器等环境，$task$ 表示任务指令。观测 $o$ 包括原始屏幕像素、无障碍树或 DOM 数据等元素。历史 $h_{<t}=\{(a_0,o_0),\dots,(a_{t-1},o_{t-1})\}$ 为智能体决策过程提供上下文。一些工作~\citep{sun2024osgenesis,xu2024aguvis} 选择为历史中的 $(a_i,o_i)$ 生成自然语言描述，因为这样能够显著节省推理成本预算。每个动作指定一种操作及相应参数，并在环境中执行；动作细节见原文附录的动作空间表。

本文坚持基于屏幕截图对计算机使用任务建模。这一范式与人类行为一致，并能有效避免带噪无障碍树和 DOM 数据的干扰。

\subsection{基础智能体模型}
\label{sec:agentmode}
\begin{figure}[t]
    \centering
    \includegraphics[width=0.9\linewidth]{figures/infer_mode.pdf}
    \caption{\textbf{计算机使用智能体的三种推理范式。}（1）\textbf{定位模式}，识别目标 UI 元素的空间坐标与边界框；（2）\textbf{直接动作模式}，智能体仅根据当前观测和指令生成可执行动作；（3）\textbf{推理动作模式}，智能体先生成思维链推理，再产生结构化动作。这些模式为计算机使用智能体完成任务提供不同层次的功能。}
    \label{fig:infer_mode}
\end{figure}
为训练鲁棒的计算机使用智能体，作者采用先进视觉语言模型 Qwen2.5-VL~\citep{bai2025qwen25vl} 作为基础模型，因为它具有强大的多模态理解能力，并能扩展到不同 GUI 平台。如图~\ref{fig:infer_mode} 所示，模型以三种模式运行：（1）\emph{定位模式}，模型根据当前观测和指令执行 UI 定位；（2）\emph{直接动作模式}，模型依据当前观测和历史上下文，直接生成带可执行动作的底层指令；（3）\emph{推理动作模式}，模型先产生推理过程，再生成动作。模型生成的输出使用 XML 标签格式化。

\textbf{定位模式}表示模型只关注 UI 元素定位。它利用视觉观测引导模型生成空间点、边界框或引用坐标的动作（如 \textit{click}、\textit{doubleClick}、\textit{moveTo} 等），以实现精确定位。在此模式下，模型仅以屏幕截图和指令作为输入。部署时，该范式可让 GPT-4o 等强大通用 VLM 充当规划器，让本文模型充当定位器，以模块化范式完成计算机使用任务。

\textbf{直接动作模式}要求模型不生成中间推理步骤或无关输出，而是高效地直接预测可执行动作。给定任务指令、当前屏幕观测和交互历史，模型同时输出一条底层指令和一个可执行动作。底层指令以简洁自然语言描述预期操作（例如“打开设置菜单”），\texttt{<action>} 标签中的动作则对应具体底层控制命令（例如 \texttt{click(x=213, y=234)}）。生成的底层指令会被追加到对话历史，作为可供人理解的描述和后续步骤的历史上下文，使模型能够在多步交互中保持上下文。底层指令与动作分别被包裹在 \texttt{<operation>...</operation>} 和 \texttt{<action>...</action>} 中。

该模式省去动作前显式的中间思考或推理步骤，从而快速执行任务。它支持精简的感知--动作闭环：模型持续观测环境并输出已定位动作。通过向交互历史加入极少但有信息量的语言反馈，智能体既能保持连贯行为，又能降低推理延迟。实证结果表明，这一设计能够高效完成复杂 GUI 任务，特别适合在线游戏等强调快速响应的实时任务。

\textbf{推理动作模式}指在生成动作前执行思维链过程，其模型输入与直接动作模式一致。推理轨迹会明确描述智能体对任务目标的解释，以及选择某个动作的理由；它通常引用屏幕中的视觉线索，并将其与用户指令联系起来。例如，模型可能先推理“任务是调节亮度。我看到右上角有一个设置图标，它很可能通向显示设置”，然后提出 \texttt{click(x=1040, y=75)} 这样的动作。中间思考过程被包裹在 \texttt{<think>...</think>} 标签中，可提高动作可靠性，尤其适用于上下文理解和逻辑定位至关重要的歧义任务或多步任务。

由于生成过程更长，该模式会引入更高的计算成本与延迟，但能显著提高智能体行为的质量和可解释性。显式推理为每一步提供人类可理解的理由，支持对决策模式和失败案例进行细粒度分析，并可用于迭代改进模型的推理启发式方法。在动作前加入结构化思考后，智能体能够以透明方式执行复杂任务，因此特别适合重视精确性和可解释性的长程交互场景。

\subsection{训练方案}
作者根据模型大小和可用硬件资源，为不同 ScaleCUA 模型采用不同配置。ScaleCUA-3B 使用 mini-batch 大小 4、梯度累积 1，在 128 张 A100 GPU 上训练。ScaleCUA-7B 使用同样的有效 batch 配置（mini-batch 大小 2、梯度累积 2）和同样的 GPU 设置。ScaleCUA-32B 的参数量显著更大，因此作者把 mini-batch 大小降为 2，并使用梯度累积 2，以维持有效 batch 大小 4；训练在 128 张 H200 GPU 上进行，以适应更高的显存占用。所有模型的学习率均为 $1.0\times10^{-5}$，最大 token 长度均为 40960。

对于所有模型，作者实验了训练语料中不同比例的通用多模态数据。3B、7B 和 32B 模型分别以 $25\%$、$50\%$ 和 $75\%$ 的通用数据比例训练。实验中，当通用数据占 GUI 专用训练语料的 $25\%$ 时，3B 模型训练后已能在 GUI 智能体基准上取得较强性能。考虑到更大模型能够记忆更多数据样本，作者将 7B 模型的比例提高到 $50\%$，并将 32B 模型进一步提高到 $75\%$。

\subsection{数据集消融实验}
本节对作者的数据集进行消融。如图~\ref{fig:teaser} 所示，使用作者整理的训练语料进行训练，相比使用公共数据训练的基线可获得一致提升。表~\ref{tab:ablation_data} 进一步展示数据增强、弱语义轨迹、坐标格式和分辨率的影响。

首先，作者评估数据增强的作用。不使用增强时，模型在 ScreenSpot-Pro 上达到 $37.8\%$；元素裁剪、屏幕截图拼接等简单增强则将性能提高到 $41.3\%$。这证实数据增强通过让模型接触更广泛的视觉条件，提高了泛化性与鲁棒性。第二，作者考察由基于规则的随机探索产生的弱语义轨迹。尽管这些轨迹缺少明确高层目标，它们仍能以较低成本为界面导航提供监督。第三，作者研究定位任务中坐标表示的影响。使用原始坐标训练的模型优于使用归一化坐标的模型（ScreenSpot-Pro 上为 $42.3\%$ 对 $37.9\%$）。这说明精确绝对位置能够更好地捕捉跨平台布局规律，减少归一化引入的歧义。最后，作者对训练分辨率进行消融。更高分辨率在不同基准间存在权衡：2K 提高 ScreenSpot-Pro 上的定位性能（$45.5\%$ 对 $42.3\%$），并基本保持 OSWorld-G 准确率（$52.5\%$ 对 $54.3\%$），但会略微降低 OSWorld 和 AndroidWorld 上的智能体成功率。这说明细粒度定位受益于高分辨率监督，而智能体基准可能因过度拟合像素级细节受到影响。UI 元素定位与在线智能体基准上的提升表明，训练数据设计是构建可扩展、可泛化计算机使用智能体的核心。

\subsection{智能体诊断分析}
\begin{figure}[t]
    \centering
    \includegraphics[width=\linewidth]{figures/exp_fig_1.pdf}
    \caption{不同条件下的评测。（a）不同屏幕截图分辨率下的 GUI 定位准确率；（b）直接动作模式与推理动作模式的成功率，推理始终提高性能；（c）训练数据扩展；（d）使用通用数据的影响，GUI 基准与多模态基准呈现不同趋势。}
    \label{fig:empirical_study}
\end{figure}
为更好地理解影响计算机使用智能体性能的因素，作者围绕分辨率、推理模式、数据扩展和是否加入通用多模态数据开展了额外分析，如图~\ref{fig:empirical_study} 所示。这些研究更深入地揭示了效率、准确率和泛化性之间的权衡。

\textbf{分辨率的影响。}图~\ref{fig:empirical_study}(a) 评测不同屏幕截图分辨率下的定位准确率。作者观察到，从 720p 提升到 2K 时，准确率持续提高；到 4K 时边际收益减弱。ScreenSpot-Pro 的受益最为明显，表明细粒度元素定位需要高分辨率细节。ScreenSpot-v2 和 OSWorld-G 中，分辨率不超过 1080p 的图像占主导，因此评测时把输入分辨率提高到 1080p 以上不会带来性能增益，有时甚至会造成轻微下降。

\textbf{直接动作模式与推理动作模式。}图~\ref{fig:empirical_study}(b) 比较计算机使用智能体的两种推理模式。在所有基准上，推理动作模式（RAM）的成功率都高于直接动作模式（DAM），绝对增益为 $1.4\%$ 至 $8.2\%$。该优势在 WebArena-Lite-v2 等复杂多步环境中尤其明显。结果表明，显式推理有助于模型保持任务连贯性，并减少长程交互中的错误传播。不过，性能提升以更高推理延迟为代价，说明不同部署场景需要在效率与鲁棒性之间进行权衡。

\textbf{随训练数据扩展的行为。}图~\ref{fig:empirical_study}(c) 展示成功率随训练数据比例变化的关系。所有基准都受益于数据增加，但增益呈对数趋势，大部分提升在数据比例超过 $75\%$ 后趋于饱和。值得注意的是，WebArena-Lite-v2 在整个范围内近似线性提升，说明它对数据规模的需求更高，也更敏感。相比之下，ScreenSpot-Pro 只使用一半可用数据就能达到有竞争力的准确率，说明某些定位基准对数据的需求较低。这一观察表明，应根据基准的内在复杂度分配数据。

\textbf{通用多模态数据的影响。}图~\ref{fig:empirical_study}(d) 分析训练中加入通用多模态数据的影响。结果呈现清晰分化：随着通用数据比例增加，GUI 基准性能逐渐下降，而通用基准性能稳定提高，并在约 $75\%$ 时达到峰值。该权衡表明，混合异构数据源会引入相互冲突的优化信号。多模态语料扩大时，模型的通用能力提高，但 GUI 专用知识会被稀释。结果说明，可能需要数据平衡训练策略，才能在不牺牲通用推理能力的同时保留 GUI 专业能力。由于更大模型能够记忆更多知识，将 7B 模型的通用数据比例提高至 $50\%$、32B 模型提高至 $75\%$ 是合理的。

\textbf{讨论。}这些结果揭示了几个关键观察。高分辨率输入与基于推理的推理方式能够改善定位和任务完成，但会产生计算成本。扩大数据规模仍然至关重要，不过不同基准对规模的敏感程度不同。最后，加入通用多模态数据会提高推理能力，却可能损害 GUI 定位准确率，因此需要谨慎设计数据混合策略。这些发现强调，要构建鲁棒的通用智能体，可扩展的跨平台训练数据非常重要。

\section{结论}
本文提出 \textbf{\modelname}：一个为 CUA 定制的新模型与数据集系列。通过整理大规模跨平台数据，并在桌面、移动端和 Web 环境间标准化动作空间，作者建立了用于评测和训练智能体的统一基础。结合自动化智能体--环境交互与人在环标注的双闭环数据流水线，使作者能够构建覆盖 GUI 理解、元素定位和任务完成的多样化基准。

大量实验表明，\modelname 显著优于开源和专有基线。在 GUI 理解任务上，\modelname{32} 在所有平台和难度等级都取得最佳准确率，凸显 GUI 专用监督的益处。在 ScreenSpot-v2、ScreenSpot-Pro 和 OSWorld-G 等定位基准上，本文模型持续刷新性能纪录，验证了细粒度元素级对齐的有效性。此外，L2-GUI 定位和在线基准上的强劲结果进一步说明模型在真实交互环境中具有鲁棒性。

这些贡献将视觉语言建模与实际 GUI 交互连接起来，推动了计算机使用智能体的前沿。尽管长程推理和跨应用泛化仍有局限，结果表明，扩展专用训练流水线有望构建鲁棒、通用的计算机使用系统。作者希望 \modelname 及其发布资源能成为未来研究的坚实基础，支持构建有能力、可信且可部署的 CUA。

\section*{局限性}
本文开发了一族基础智能体模型，并建立了用于收集跨平台 GUI 交互轨迹的全面数据流水线。尽管如此，仍存在若干局限。

第一，由智能体采集的数据在质量上仍落后于专家众包。基于规则的探索通常产生语义较弱的轨迹，而专家整理数据又很难以低成本扩展。如何把自动化采集与迭代式模型改进有效耦合，形成自我改进闭环，仍是一个开放挑战。

第二，尽管本文重点是为跨平台计算机使用智能体构建鲁棒基础模型，但尚未加入反思、基于记忆的决策或层次化规划等高级智能体机制。此外，作者也没有探索策略奖励模型（Policy Reward Model，PRM）或强化学习等优化策略。这些技术有望提高推理、适应和长程决策能力，但需要以强大的基础模型为前提。

第三，当前记忆机制较为初级，只把先前操作视为扁平历史。这种浅层设计限制了长程推理，并可能造成次优执行。本文的主要目标是利用大规模 GUI 语料训练具备强泛化和指令遵循能力的基础智能体模型。开发能够捕获时间依赖、轻量而有效的记忆系统，是未来工作的重要方向。

综上，尽管本文框架为训练 GUI 智能体提供了统一基础，要实现闭环学习和高层推理能力仍需进一步研究。解决这些局限对于实现完全自主、智能的计算机使用智能体至关重要。
