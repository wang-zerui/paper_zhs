\section{相关工作}
\label{sec:related}

\nospacestitle{LLM 请求的全局调度。\,}
{\sys} 延续了在集群中调度 LLM 请求这一研究方向~\cite{vllm,DBLP:journals/corr/abs-2506-05871,DBLP:conf/iclr/SrivatsaHAL025,
305212,DBLP:journals/corr/abs-2507-17769,llm-d}。
据我们所知，这些方法都试图通过三类方式组合不同指标，从而同时实现 {\kvcache} 感知和负载均衡；我们已在 \textsection{\ref{sec:principles}} 中对此进行了详细讨论。
{\sys} 建立在这些工作的基础上，复用了它们所使用的指标，但进一步提出了一种新的、简单的乘法组合器；大量评估结果也验证了这种方法的有效性。

\stitle{实例内部的 LLM 请求调度。\,}
除了跨实例的全局调度之外，还有一类工作关注实例内部的局部调度优化。
Sarathi-Serve~\cite{298679} 提出了 chunked prefill，将长预填充请求切分为更小的块，以减少与之同置的解码请求的停顿时间。
VTC~\cite{DBLP:conf/osdi/0007CLZ0ZGS24} 采用基于 token 的准入控制机制来实现公平性。
FairBatching~\cite{DBLP:journals/corr/abs-2510-14392} 使用线性时间分析模型，在预填充与解码 token 之间进行优先级决策，并动态构造批次。
这些工作与我们的全局调度是正交的；而一个好的全局调度器还能进一步增强局部调度的效果，例如减少“实例过载”这类仅靠局部调度难以解决的问题发生的频率。

\stitle{LLM 服务优化。\,}
除调度之外，研究界还提出了多种提升 LLM 服务性能的技术。
其中包括提升 {\kvcache} 命中率的方法~\cite{305212,10.5555/3768039.3768067}、
为模型服务提供弹性的机制~\cite{DBLP:conf/osdi/ZhangWLWS0025,DBLP:conf/sosp/Xiang0QYZYZL0025}，
以及优化 GPU 执行效率的方法~\cite{vllm,DBLP:conf/asplos/KamathPM0RP25}，等等。
据我们所知，这些技术都可以与调度优化共存，因此也能够与 {\sys} 结合，进一步提升整体性能。
