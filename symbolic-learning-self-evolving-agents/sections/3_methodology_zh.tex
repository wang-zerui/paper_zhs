\subsection{问题形式化}

我们首先通过类比神经网络训练中的组件和过程，对\baby{}框架进行形式化。下面定义框架的关键组件，并说明本节使用的符号。

如图~\ref{fig:workflow}所示，\baby{}框架受神经网络训练所采用的联结主义学习过程~\citep{hinton1990connectionist}启发。我们先借助与联结主义学习框架的类比，引入关键概念的记号：

\begin{itemize}
    \item \textbf{智能体流水线} $\Pipeline$：神经网络中的计算图表示各层的结构及其连接；与之类似，\textit{智能体流水线}表示智能体处理输入数据时依次经过的节点（或步骤）。它由一系列节点 $\{\Node_1, \Node_2, \ldots, \Node_n\}$ 构成，这些节点分阶段处理输入数据。需要注意，在某些智能体框架中，节点会在执行期间动态分配，因此智能体流水线依赖于输入；这与动态神经网络的情形相似。

    \item \textbf{节点} $\Node$：智能体流水线中的一个独立步骤。节点在智能体中的作用，类似于神经网络中的一层。节点 $\Node_n$ 接收同样采用自然语言形式的\textbf{节点输入} $\NodeInput$。一般而言，一个节点的输入由前一节点的输出以及（可选的）环境输入（例如人类输入）组成。节点 $\Node_n$ 使用 LLM，并结合\textbf{提示} $\NodePrompt$ 和\textbf{工具} $\NodeTool$\footnote{$\NodeTool$ 包括工具使用时的输入与输出，以及工具本身的实现。}处理输入 $\NodeInput$。输出 $\NodeOutput$ 采用自然语言形式，并传递给下一个节点。

    \item \textbf{轨迹} $\Trajectory$：轨迹的作用类似于神经网络的计算图。它存储前向传播期间的全部信息，包括每个节点的输入、输出、提示和工具使用情况，并负责梯度的反向传播。

    \item \textbf{语言损失} $\LanguageLoss$：\baby{}框架中的语言损失与神经网络损失相似，因为二者都衡量期望结果与实际结果之间的差异。主要区别在于：语言损失采用文本形式，由精心设计的提示所实现的自然语言损失函数生成；传统损失则是由数值方程形式的损失函数计算出的浮点数。

    \item \textbf{语言梯度} $\LanguageGradient$：与梯度在联结主义学习中的作用类似，\textit{语言梯度}是相对于语言损失、用于更新智能体中各组件的文本分析与反思。
\end{itemize}

\subsection{智能体符号学习过程}

定义关键组件后，我们可以用算法~\ref{algo:main}概括\baby{}框架的工作流程。本节将详细说明其中的每一步。

\paragraph{前向传播}
前向传播与标准的智能体执行几乎完全相同。主要区别是，我们会把输入、提示、工具使用情况和输出保存到轨迹中，供语言梯度反向传播使用。这类似于 PyTorch~\citep{paszke2019pytorch}和 TensorFlow~\citep{abadi2016tensorflow}等深度学习框架：它们会把中间输出和激活值存储在神经网络的计算图中。

\paragraph{语言损失计算}
完成前向传播后，我们把轨迹输入 LLM，并使用精心设计的提示模板 $\mathcal{P}_{\text{loss}}$，为一个训练样本计算语言损失：
\begin{equation}
    \LanguageLoss = \text{LLM}( \mathcal{P}_{\text{loss}}(\Trajectory))
\end{equation}
关键在于提示模板的设计：它应当相对于输入、环境和任务要求，对智能体表现进行\textit{整体性}评估。为此，我们精心设计了用于语言损失计算的提示模板，它由以下部分组成：任务描述、输入、轨迹、少样本示例、原则和输出格式控制。其中，任务描述、输入和轨迹依赖于数据，而少样本示例、原则和输出格式控制对所有任务及训练样本保持固定。语言损失同时包含自然语言评论和数值分数（后者同样通过提示生成）。生成语言损失时，我们可以选择把输入对应的真实标签一并提供；我们把这种情形称为\textit{有监督智能体学习}。框架也可以不依赖真实标签，而是根据任务描述评估输出和轨迹并生成语言损失；此时可称智能体正在进行\textit{无监督智能体学习}，这使语言智能体能够自我演化。该提示模板的具体实现见附录中的原文材料。

\paragraph{语言梯度的反向传播}
在标准联结主义学习中，梯度反向传播旨在计算各权重对总体损失的影响，以便优化器据此更新权重。类似地，我们也为语言梯度设计了一种“反向传播”算法。具体来说，我们从最后一个节点反向迭代至第一个节点，并用精心设计的提示让 LLM 为每个节点计算梯度：
\begin{equation}
    \NodeGradient = \text{LLM}(\mathcal{P}_{\text{gradient}}(\PreviousNodeGradient, \NodeInput, \NodeOutput, \NodePrompt, \NodeTool, \LanguageLoss))
\end{equation}
提示模板 $\mathcal{P}_{\text{gradient}}$ 用于指示 LLM 生成语言梯度，即针对节点内符号组件的分析与反思。受反向传播思想启发，我们把当前节点之后所执行节点的语言梯度，以及轨迹中保存的当前节点执行信息，一并提供给 LLM。也就是说，在分析和反思时，LLM 不仅要考虑提示和工具是否适合当前节点的子目标，还必须考虑它们如何影响下一节点子目标的完成。通过从后向前逐一链接，所有节点的语言梯度都与智能体的整体成功相关，并对其负责。该方法有效降低了分别优化各孤立提示与工具时趋向局部最优的风险，从而改善智能体系统的整体性能。

\paragraph{基于语言梯度的更新}
框架的最后一步，是借助语言梯度更新各节点中的提示和工具，并优化整体智能体流水线。这通过“符号优化器”完成。符号优化器是精心设计的提示流水线，能够优化智能体的符号权重。我们构建了三类符号优化器：PromptOptimizer、ToolOptimizer 和 PipelineOptimizer。相关提示的具体实现见附录中的原文材料。

\noindent\textbf{PromptOptimizer：}为便于提示优化，我们把提示拆分为不同组件，包括任务描述、少样本示例、原则和输出格式控制。随后，针对每一种提示组件的优化分别设计提示。所有这些提示都包含详细说明和示范，告诉 LLM 在推理如何编辑原始提示组件时，应当怎样聚焦语言梯度。

\noindent\textbf{ToolOptimizer：}ToolOptimizer 是一条提示流水线。它首先指示 LLM 决定应采用哪类操作：是改进工具（通过编辑函数调用所用的工具描述）、删除工具，还是实现新工具。随后，ToolOptimizer 会调用分别为工具编辑、删除和创建而设计的不同提示。

\noindent\textbf{PipelineOptimizer：}PipelineOptimizer 的目标，是优化由节点及其连接构成的智能体流水线。提示首先介绍用于定义智能体流水线的智能体编程语言（本文采用\citet{zhou2023agents}所提出的智能体编程语言）。接着，提示描述若干可供 LLM 更新流水线的原子操作定义，包括添加、删除和移动节点。然后，它指示 LLM 先分析流水线可以怎样改进，再用这些原子操作实现更新。智能体编程语言以及更新流水线所用原子操作的详细说明，见附录中的原文材料。

由于上述优化器都在自然语言空间中运行，而部分优化操作需要在代码空间中完成，我们采用一种简单策略：任何非法更新最多重试三次；若错误仍然存在，就丢弃该更新。我们还采用回滚策略：优化后重新运行当前样本；如果基于语言的损失函数所评估的性能下降，则回滚到原始智能体。此外，我们在优化器的每个提示中都加入一个“学习率”组件，用来控制 LLM 优化提示、工具和智能体流水线时的激进程度。

\paragraph{批量训练}
上述优化方案每次处理一个训练样本，类似于随机梯度下降。受小批量随机梯度下降在实践中效果更好、或更稳定这一事实启发，我们也为符号优化器设计了批量训练变体。具体来说，先分别对每个样本执行前向传播、损失计算和反向传播；随后，把同一节点的一批语言梯度共同输入 LLM，并通过提示让 LLM 在更新智能体时整体考虑所有这些语言梯度。
