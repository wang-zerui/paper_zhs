\section{相关工作}
\textbf{解耦内存与前缀缓存。}
已有工作尝试将 KV 缓存管理从计算中解耦，以缓解碎片化和负载不均问题。例如 TokenLake \cite{tokenlake} 提出了带统一前缀池的解耦式内存架构，用于减少不同实例之间的冗余。尽管这类方法能够改善空间利用效率，但它们并未处理离线 Agent 推理中固有的\emph{时间维度上的过量承诺}问题。在该场景下，并发 Agent 会在中期同时扩展上下文，即使采用统一缓存池，也仍可能被压垮。我们的工作与其互补，通过引入主动流量控制来避免内存饱和。

\textbf{面向应用结构的 Serving。}
近期一些系统开始超越请求级调度，通过利用应用结构来降低时延和任务完成时间。Parrot \cite{parrot}、Teola \cite{teola}、Autellix \cite{autellix} 与 Kairos \cite{kairos} 等方法利用 DAG、依赖感知或内存预测来重排请求，以减轻多轮工作负载中的阻塞。它们通常假设内存压力可以通过淘汰或重排来处理。相比之下，我们关注的是大批量离线场景，在这里无论调度顺序如何，过高并发都会引发抖动，因此系统需要显式的\emph{准入控制}。

\textbf{Agent 原生推理与并发控制。}
Agent 执行在 GPU 生成与 CPU 侧工具调用之间交替进行，这使内存管理更为复杂。TokenCake \cite{tokencake} 和 Continuum \cite{continuum} 主要依赖卸载、基于 TTL 的缓存固定等被动机制来处理这一问题。我们的方案则有本质差异：受网络拥塞控制启发，我们使用 AIMD 主动调节 Agent 并发，以限制内存压力并消除中期抖动，而不是依赖代价高昂的交换操作。
