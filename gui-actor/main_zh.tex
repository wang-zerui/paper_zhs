\begin{abstract}
构建由 VLM 驱动的 GUI 智能体时，一个主要挑战是视觉定位，即根据视觉内容和文本计划，为动作执行定位合适的屏幕区域。大多数已有工作把它表述为基于文本的坐标生成任务。然而，这类方法存在若干限制：由于缺少显式空间监督，空间-语义对齐较弱；由于单点预测会惩罚有效变化，难以处理有歧义的监督目标；并且屏幕坐标是密集的，而 Vision Transformer 等模型提取的视觉特征是粗粒度 patch 级特征，两者之间存在不匹配。本文提出 \sys，一种基于 VLM 的无坐标 GUI 定位方法。\sys 的核心是一个注意力式动作头，它学习将专用的 \texttt{<ACTOR>} token 与所有相关视觉 patch token 对齐，使模型能够在单次前向传播中提出一个或多个动作区域。与此相配合，我们进一步设计了一个定位验证器，用于评估候选区域，并从中选择最可能用于动作执行的区域。
大量实验表明，在多个 GUI 动作定位基准上，\sys 优于已有最新方法，并且对未见过的屏幕分辨率和布局具有更好的泛化能力。
值得注意的是，\textbf{GUI-Actor-7B} 以 Qwen2-VL 和 Qwen2.5-VL 为骨干时，在 ScreenSpot-Pro 上分别取得 \textbf{40.7} 和 \textbf{44.6} 的分数，超过 \textbf{UI-TARS-72B}（\textbf{38.1}），同时参数量和训练数据显著更少。
此外，通过引入验证器，我们发现只微调新引入的动作头（7B 模型约 $\sim$100M 参数）并冻结 VLM 骨干，就足以达到与已有最新模型相近的性能。这说明 \sys 能够在不损害底层 VLM 通用能力的情况下，为其赋予有效的定位能力。项目页面：\url{https://aka.ms/GUI-Actor}。

\section{GUI-Actor 的设计}
\label{sec:method}

考虑到基于文本的坐标生成存在空间-语义对齐较弱、监督目标有歧义等限制，我们从人类与 GUI 交互的方式中获得启发。
人类通常并不会计算精确坐标，而是先从视觉上识别目标元素，然后通过手指点击或移动鼠标光标直接作用于该元素。
受此启发，\sys 探索了一种用于 GUI 视觉定位的新型架构：我们首先引入一个特殊 token \texttt{<ACTOR>} 作为上下文锚点，然后训练一个动作注意力头，使该锚点关注与目标元素对应的图像 patch。最后，我们提出一个定位验证器，用于从注意力图导出的多个候选目标中选择语义上最合适的目标。

\paragraph{\texttt{<ACTOR>} Token 作为上下文锚点}
给定一张截图图像 $\mathcal{I}$ 和一条指令 $q$，基于坐标生成的方法通常训练 VLM 生成序列 $\{\bm{x}_{1:i-1}, \bm{x}_{i:i+m}, \bm{x}_{i+m+1:j-1}, \bm{x}_{j:j+n}, \bm{x}_{j+n+1:N}\}$，其中 $m, n >0 $，$N$ 是输出序列总长度，$i > 1$，并且 $j-1 > i+m+1$。
例如，在 \texttt{pyautogui.click(x=0.123, y=0.234)}~\citet{xu2024aguvis} 中，片段 $\bm{x}_{i:i+m}$ 和 $\bm{x}_{j:j+n}$ 分别对应分词后的 x 坐标和 y 坐标。
片段 $\bm{x}_{i+m+1:j-1}$ 表示二者之间的分隔符，而其余部分捕获周围上下文。
在本文中，我们用三个特殊 token 替换坐标片段 $\{\bm{x}_{i:i+m}, \bm{x}_{i+m+1:j-1}, \bm{x}_{j:j+n}\}$，以支持无坐标定位，并更好地融合视觉输入和文本指令中的上下文：
\begin{equation}
    \text{VLM}(\mathcal{I}, q) = \{\bm{x}_{1:i-1}, \texttt{<ACTOR\_START>}, \texttt{<ACTOR>}, \texttt{<ACTOR\_END>}, \bm{x}_{i+3:N}\}.
\end{equation}
我们使用 \texttt{<ACTOR>} 的最后一层隐藏状态，即 $h_{\texttt{<ACTOR>}}$，作为上下文锚点，用于在视觉 patch token 上计算动作注意力。

\paragraph{注意力式动作头}
令 ${v_1, \dots, v_M}$ 表示 VLM 的视觉编码器从输入截图中提取的视觉 patch 特征，其中每个 $v_i \in \mathbb{R}^d$。
动作头从 \texttt{<ACTOR>} token 出发，在这些视觉 patch 上计算注意力分布，以识别目标动作区域。
为了融入面向 GUI 的上下文信息，我们首先对视觉 patch 特征应用自注意力层。这使模型能够在空间相关的 patch 之间聚合语义，让属于同一个 GUI 元素的 patch 共享一致表示：
\begin{equation}
\tilde{v}_1, \dots, \tilde{v}_M = \text{SelfAttn}(v_1, \dots, v_M),
\end{equation}
其中 $\tilde{v}_i \in \mathbb{R}^d$ 表示自注意力模块之后第 $i$ 个 patch 的上下文化特征。

接着，我们通过两个独立的 MLP，把 \texttt{<ACTOR>} token 表示 $h_{\texttt{<ACTOR>}}$ 和上下文化 patch 特征 ${\tilde{v}_1, \dots, \tilde{v}_M}$ 投影到共享嵌入空间，得到 $z$ 和 $z_i \in \mathbb{R}^d$：
\begin{equation}
z = \text{MLP}_{\text{T}}(h_{\texttt{<ACTOR>}}), \quad z_i = \text{MLP}_{\text{V}}(\tilde{v}_i).
\end{equation}
最后，我们计算 \texttt{<ACTOR>} token 与每个视觉 patch 之间的注意力分数。令 $M$ 表示输入到 LM 骨干的图像特征总数，得到的注意力权重 ${a_1, \dots, a_M}$ 构成屏幕上的注意力图，指示与动作定位最相关的区域。

\begin{equation}
\begin{array}{ll}
\displaystyle \alpha_i = \frac{z^\top z_i}{\sqrt{d}}, &
\displaystyle a_i = \frac{\exp(\alpha_i)}{\sum_{j=1}^M \exp(\alpha_j)}, \quad \text{for } i = 1, \dots, M.
\end{array}
\end{equation}

\paragraph{空间感知多 Patch 监督}
我们方法的一个关键优势，是能够利用来自边界框监督的密集且具有空间结构的学习信号。不同于传统坐标方法依赖单个、可能有歧义的点击点，\sys 把所有被真实边界框部分或完全覆盖的图像 patch 作为正例（$y_i$=1），其余作为负例（$y_i=0$），其中 $y_i$ 表示与 $v_i$ 关联的标签。这使模型能够更有效地捕获可操作元素的完整空间范围。\Cref{fig:multipatch} 给出了示意图。更多细节见附录~\ref{appendix:multi_path_supervision}。

我们使用下一 token 预测（NTP）损失和动作注意力损失的组合来训练模型：
\begin{equation}
\mathcal{L} = \mathcal{L}_{\text{NTP}} + \mathcal{L}_{\text{Action\_Attn}},
\end{equation}
动作注意力损失定义为：
\begin{equation}
\mathcal{L}_{\text{Action\_Attn}} = \sum_{i=1}^M p_i \log \frac{p_i}{a_i}, \quad p_i = \frac{y_i}{\sum_{j=1}^M y_j + \epsilon}, ~i = 1, \dots, M,
\end{equation}
其中 $\epsilon$ 是用于数值稳定性的小常数。

\section{定位验证器}
我们的注意力式动作定位模型有一个关键优势：它可以在单次前向传播中产生多个候选动作区域，而不增加额外推理成本。这是注意力式设计的自然结果，因为模型会同时为所有视觉 patch 分配分数。这种效率带来一个机会：我们无需只依赖得分最高的 patch，而可以引入一个轻量级验证步骤，从候选中选择语义上最合适的目标。

基于“验证通常比生成更容易”这一观察~\citep{cobbe2021training}，我们提出一个 \textit{Grounding Verifier}。它是一个轻量级 VLM 模块，以指令和带有视觉标记的截图作为输入，并预测被标记区域是否正确满足任务意图。该验证器作为决策细化层，使系统能够在执行前反思其动作。

\paragraph{数据与训练}
验证器训练数据来自 OS-Atlas 数据集~\cite{wu2024atlas}，该数据集覆盖桌面、移动端和 Web 领域。
数据集提供形式为 $(\text{image}, \text{query}, \text{bounding box})$ 的三元组，其中每张图像与多条查询及其对应边界框相关联。对每个三元组，我们通过在边界框中心放置视觉标记（\ie 空心红圈）生成一个\textit{正例}，把它视为给定查询的正确定位点。
为了构造\textit{负例}，我们采用两种策略：（1）选择同一图像中错误边界框的中心；（2）在目标区域外随机采样一个点。每个得到的训练样本格式化为元组 $(\mathcal{I}, \mathbf{x}, y)$，其中 $\mathcal{I}$ 是带有标记点的图像，$\mathbf{x}$ 是对应语言指令，$y \in \{\texttt{`True'}, \texttt{`False'}\}$ 是真实标签，表示该点是否正确满足指令。更多细节见附录~\ref{appendix:data_verifier}。

我们从一个轻量级 VLM 微调验证器，并使用标准监督学习。模型以 $(\mathcal{I}, \mathbf{x})$ 作为输入，训练目标是生成正确 token $y$。训练目标为交叉熵损失：
\[
\mathcal{L}_{\text{Verifier}} = - \log P_{\theta_v}(y \mid \mathbf{I}, \mathbf{x}),
\]
其中 $P_{\theta_v}$ 表示参数为 $\theta_v$ 的验证器模型输出概率。

\paragraph{推理}
推理时，\sys 通过结合自然语言生成和视觉定位来预测最终动作位置。给定当前 GUI 状态和用户指令，\sys 首先通过标准解码生成智能体响应，例如产生包含特殊 \texttt{<ACTOR>} token 的字符串 \texttt{pyautogui.click(<ACTOR\_START><ACTOR><ACTOR\_END>)}。随后，我们提取 \texttt{<ACTOR>} 对应的隐藏状态，并使用动作头在所有视觉 patch 上计算注意力。该注意力分布作为空间激活图，用于识别执行预测动作时最相关的屏幕区域。

为了在 top-$K$ 注意力加权 patch 中识别语义上最合适的区域，我们用验证器 $\theta_v$ 为每个候选打分：在图像 $\mathcal{I}$ 上标记该候选，并评估其与指令 $x$ 的对齐程度。对每个带标记图像，验证器输出 \texttt{`True'} 和 \texttt{`False'} token 的概率，我们将选择分数定义为：
\begin{equation}
\texttt{s}(\mathcal{I}, x) = \frac{P_{\theta_v}(\texttt{`True'} \mid \mathcal{I}, x)}{P_{\theta_v}(\texttt{`True'} \mid \mathcal{I}, x) + P_{\theta_v}(\texttt{`False'} \mid \mathcal{I}, x)}.
\end{equation}

候选会按注意力权重降序评估；一旦某个候选超过置信度阈值（例如 $\texttt{s}(\mathcal{I}, x) > \gamma$），我们便返回该候选，不再继续评估。

\section{实验}

\paragraph{实现细节}
我们使用 PyTorch 和 Huggingface Transformers 实现 \sys。
除非另有说明，我们采用 Qwen-2-VL-7B-Instruct~\cite{wang2024qwen2} 作为 \sys 和基线的骨干 VLM，以保证与已有最新方法公平比较。
对于使用点监督 \textit{(point sup.)} 和边界框监督 \textit{(bbox sup.)} 的 Aguvis-7B 基线复现，我们直接使用 Aguvis~\cite{xu2024aguvis} 提供的官方源代码。
对动作头的所有配置，我们使用与骨干 VLM 相同的维度。
定位验证器从 UI-TARS-2B-SFT~\cite{qin2025ui} 微调而来。推理时，我们构造 $K=20$ 个候选，并在 ScreenSpot-Pro 上使用 $\gamma=0.95$ 的置信度阈值，在 ScreenSpot 和 ScreenSpot-v2 上使用 $\gamma=0.8$。
遵循 Aguvis~\citep{xu2024aguvis}，我们把训练数据组织为 \texttt{pyautogui} 风格操作序列，但按第~\ref{sec:method} 节所述，用特殊 token 替换原始坐标。
完整训练配方由多个公开 GUI 数据集构成，包含约 $\sim$1M 张截图。
\sys 和两个基线模型均使用表~\ref{tab:train-data} 总结的数据配方训练 1 个 epoch。更多数据集细节见 \Cref{app:datasets}。
训练 \sys 时，我们先冻结所有骨干 VLM 参数，只训练动作头中新引入的组件（2B/7B 骨干分别约 $\sim$20M/$\sim$100M 参数）。在这一热身阶段之后，我们使用标准监督学习微调整个模型。

\paragraph{评测基准与指标}
我们在三个成熟的 GUI 视觉定位基准上评测 \sys 和其他基线方法：ScreenSpot~\cite{cheng2024seeclick}、ScreenSpot-v2~\cite{wu2024atlas} 和 ScreenSpot-Pro~\cite{li2025screenspot}。其中 ScreenSpot-Pro 包含更高分辨率界面和更大的领域偏移（例如工业软件、多窗口布局），是评估泛化能力的实用测试平台。
评测指标采用 \textit{Element Accuracy}，衡量预测点击点落在目标元素真实边界框内的比例。更多基准信息见附录~\ref{sec:grounding_benchmark}。

\paragraph{基线}

\paragraph{主要结果}
表~\ref{tab:screenspot_pro}、表~\ref{tab:screenspot}、表~\ref{tab:screenspot_v2} 和表~\ref{tab:qwen25vl} 展示了 ScreenSpot-Pro、ScreenSpot 和 ScreenSpot-v2 基准上的性能比较。

\paragraph{稳健的分布外泛化}

\section{结论}
我们提出了 \sys，一种面向 GUI 智能体的新型无坐标视觉定位框架。
不同于主流基于文本的坐标生成范式，\sys 引入专用的 \texttt{<ACTOR>} token，通过关注目标视觉 patch，直接在屏幕上定位 GUI 元素。
该机制显式对齐空间视觉特征与指令中的语义信号，并天然支持基于边界框的多 patch 监督，从而缓解单点预测固有的歧义。
得益于单次前向传播中提出多个候选区域的能力，\sys 进一步使用轻量级验证器在推理时选择最可信目标。
多个基准上的实验表明，\sys 优于最新方法，并且对未见过的布局和屏幕分辨率具有更强泛化能力。
我们进行了大量分析以理解框架中各组件的有效性，凸显其推动视觉 GUI 智能体发展的潜力。

\section{局限性}\label{app:limitations}
我们的注意力式动作生成特别适合 GUI 环境，因为图标、文本行等界面元素通常呈现规则几何模式，并天然适配基于 patch 的检测。然而，一个限制来自我们采用的基础模型：骨干 VLM（\eg Qwen2-VL）使用固定 patch 大小为 $28\times28$ 像素的 Naive Dynamic Resolution 策略。当处理非常小的界面元素时（例如小于 $10\times10$ 像素的图标），这会带来挑战，因为这类细粒度细节可能无法被充分表示。尽管这一挑战并非我们方法独有，但在需要高精度控制的任务中会更加明显，例如 CAD 工具等专业软件。虽然本文引入了一个简单缓解策略，但要完全解决该限制，未来可能需要更实质性的进展，例如提升视觉编码器的感知分辨率，或引入基于偏移量的空间细化。

\section{多 Patch 监督细节}
\label{appendix:multi_path_supervision}
我们方法的一个关键优势在于，能够利用来自边界框的密集且有空间结构的监督。不同于依赖单个、可能有歧义点击点的传统坐标方法，\sys 能够在整个目标区域上进行监督，从而更有效地捕获可操作元素的空间范围。\Cref{fig:multipatch} 给出了一个示例。

具体而言，我们把每个真实边界框转换为 $W \times H$ 图像 patch 网格上的二值掩码。
给定归一化边界框 $b = [\text{left}, \text{top}, \text{right}, \text{bottom}] \in [0,1]^4$，我们将归一化坐标缩放到 patch 网格分辨率：
\begin{equation}
\left( \lfloor \text{left} \cdot W \rfloor,\; \lfloor \text{top} \cdot H \rfloor,\; \lceil \text{right} \cdot W \rceil,\; \lceil \text{bottom} \cdot H \rceil \right).
\end{equation}
这种取整保证所有被边界框部分或完全覆盖的 patch 都纳入监督区域。
索引位于所得网格对齐区域内的所有 patch 标为正例（即掩码值为 1），其他 patch 的值设为 0。
由此得到一个与图像 patch 序列对齐的二值向量 $\mathbf{y} \in \{0, 1\}^M$，其中 $M = W \times H$。

我们将动作头损失定义为预测注意力分布 $\{a_1, \dots, a_M\}$ 与由二值掩码 $\mathbf{y} \in \{0, 1\}^M$ 导出的归一化目标分布 $\mathbf{p}$ 之间的 KL 散度：
\begin{equation}
\begin{aligned}
\displaystyle p_i &= \frac{y_i}{\sum_{j=1}^M y_j + \epsilon}, \: \text{for } i = 1, \dots, M; \quad
\displaystyle \mathcal{L}_{\texttt{<ACTOR>}} &= \sum_{i=1}^M p_i \log \frac{p_i}{a_i},
\end{aligned}
\end{equation}
其中 $\epsilon$ 是用于数值稳定性的小常数。

# This may differ from width // patch_size due to image reshaping.
# Qwen2-VL's Naive Dynamic Resolution may require W // 2 and H // 2.

scores = np.array(json_prediction['attn_scores'][0]).reshape(H, W)

# Normalize the attention weights for coherent visualization
scores_norm = (scores - scores.min()) / (scores.max() - scores.min())

# Resize the attention map to match the image size. You can choose different resize strategies, such as NEAREST and BILINEAR.
score_map = Image.fromarray((scores_norm * 255).astype(np.uint8)).resize((width, height), resample=Image.BILINEAR)

# Apply colormap
colormap = plt.get_cmap('jet')
colored_score_map = colormap(np.array(score_map) / 255.0)  # returns RGBA
colored_score_map = (colored_score_map[:, :, :3] * 255).astype(np.uint8)
colored_overlay = Image.fromarray(colored_score_map)

# Blend with original image
blended = Image.blend(image, colored_overlay, alpha=0.3)
\end{lstlisting}

\subsection{Patch 选择}
\label{appendix:patch_selection}
给定注意力图中的 top $M$ 候选 patch，我们的目标是选择图像中最符合用户指令的一个位置。一个直接做法是在每个 patch 中心绘制标记，并用验证器评估该位置满足指令 $x$ 的程度。具体而言，对于每张带标记点的候选图像 $I$，我们用验证器 $\theta_v$ 计算预测 \texttt{`True'} 或 \texttt{`False'} token 的概率：
$P_{\texttt{true}} = P_{\theta_v}(\texttt{`True'}|I,x)$ 和 $P_{\texttt{false}} = P_{\theta_v}(\texttt{`False'}|I,x)$。随后，我们把每个位置的分数定义为 \texttt{`True'} token 的归一化概率：$\texttt{s}(I,x)=\frac{P_{\texttt{true}}}{P_{\texttt{true}} + P_{\texttt{false}}}$。

该方法的一个关键限制是，每个 patch（通常为 $28 \times 28$ 像素）可能错过位于两个相邻 patch 之间的小图标，从而导致目标定位不准确。为了解决这一点，我们引入一个简单而有效的细化策略。我们首先对 4 连通的相邻 patch 聚类，并基于各 patch 的验证器分数计算加权中心。这样可以生成位于相邻 patch 之间的候选点，并在不直接修改基础模型 patch 大小的情况下提高定位精度。

在实现中，我们最多使用 $M=20$ 个最高分 patch，并过滤掉注意力权重低于最大注意力权重 20\% 的 patch。随后，我们对相邻 patch 聚类，计算这些簇的加权中心，并将其加入 $M$ 个候选位置集合。每个候选位置都用 $\texttt{s}(I,x)$ 打分，并选择得分最高者。给定候选坐标 $(x, y)$，我们以 $(x, y)$ 为中心裁剪大小为 $l_{\text{crop}} \times l_{\text{crop}}$ 的方形图像区域。实现如下：
\begin{lstlisting}[language=Python]
image.crop((
    max(0, x - l_crop//2),
    max(0, y - l_crop//2),
    min(image.size[0], x + l_crop//2),
    min(image.size[1], y + l_crop//2)
))
\end{lstlisting}
所有任务中我们都设置 $l_{\text{crop}} = 1000$ 像素。为了降低计算成本，如果某个候选位置达到高置信度分数（例如 $\texttt{s}(I, x) > 0.95$），我们会立即返回该位置，而不再评估剩余候选。在实验中，我们对 ScreenSpot-Pro 任务设置阈值 0.95，对 ScreenSpot 和 ScreenSpot-v2 设置 0.8。较低阈值会减少对验证器的依赖，更多信任定位模型输出，适用于定位模型本身已经很准确的情况。相反，较高阈值会促使验证器更仔细地评估每个候选，这在 ScreenSpot-Pro 等定位模型较不可靠的场景中更有益。

\subsection{通过验证器自聚合增强生成}
\label{app:verifier_agg}

\subsection{与使用验证器的基线比较}\label{app:baseline_w_verifier}
为了进一步验证定位验证器的有效性，我们把它接入 AGUVIS 基线：在推理时采样多个候选位置，并选择验证器分数最高的位置。具体而言，AGUVIS 在 temperature 0.0 下生成一个确定性输出，并用 temperature 0.7 额外采样 20 个候选点。尽管该方法探索了更广范围的合理位置，但会为这些模型带来显著计算开销。

相比之下，GUI-Actor 使用注意力图在单次前向传播中提出多个候选点。这带来高效得多的流程：与 AGUVIS 相比，\textbf{只需约 5\% 的计算量}，同时在 ScreenSpot 和 ScreenSpot-v2 上取得明显更高的定位准确率，并在更具挑战的 ScreenSpot-Pro 基准上显著超过 AGUVIS。这些结果同时展示了 GUI-Actor 的效率，以及验证器在改进行动选择方面的通用有效性，即使接入其他模型也是如此。

\section{OSWorld 在线基准评测}
\label{sec:online_eva}

为了评估所提出 \sys 在真实世界中的有效性，我们在 OS-World~\citep{xie2024osworld} 上使用 \textit{GUI-Actor-7B} 进行快速验证。OS-World 是一个实时基准，用于测试真实桌面环境中的 GUI 智能体。我们关注一个包含 49 个 Windows 专用任务的精选子集，记为 OSWorld-W，覆盖多种多步办公和多应用场景。每个任务都配有手写验证脚本，以保证可靠的自动评测。

遵循标准评测流水线，我们采用 GPT-4o 作为规划器。在每一步中，规划器观察当前 GUI 截图和用户指令，并生成自然语言计划。随后，该计划由底层定位模型通过基于坐标或无坐标机制定位为具体动作；定位模型在决定智能体成功与否时起关键作用。

我们将 \sys 与若干最新视觉定位基线比较：Aguvis-7B~\citep{xu2024aguvis}、NAVI~\cite{bonatti2024windows} 和 OmniAgent~\cite{lu2024omniparser}。如表~\ref{tab:osw} 所示，\sys 取得最高任务成功率 12.2\%，超过 OmniAgent 和 NAVI（均为 10.2\%），并大幅超过 Aguvis-7B（4.0\%）。这些结果凸显了 \sys 在复杂真实 GUI 环境中的有效性和鲁棒性。尽管训练时未接触 OSWorld-W 任务，\sys 仍能很好泛化到未见场景，比已有替代方案提供更准确且可靠的定位性能。
