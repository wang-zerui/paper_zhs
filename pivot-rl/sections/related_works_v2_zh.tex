\subsection{智能体 LLM 与训练方案}
智能体语言模型会在自然语言与接地动作之间交替，从而完成跨工具、代码与网页导航的复杂环境交互 \citep{yao2023react,schick2023toolformer,xu2023toolbench,qin2023toolllm,shridhar2020alfworld,wang2022scienceworld,jimenez2024swebench,wang2025openhandsopenplatformai,pan2025trainingsoftwareengineeringagents,yao2022webshop,wei2025browsecompsimplechallengingbenchmark,ma2024agentboard,wang2024sotopiapi}。强化学习（RL）进一步优化了多轮探索与信用分配 \citep{ouyang2022training,schulman2017ppo,schulman2015trpo,wang2025sparl,song2024trialerror,zhang2025rlvmr}，并受益于近来在可扩展策略优化、分层建模与多智能体协同方面的进展 \citep{ji2025treesearchllmrl,rohatgi2025tamingprocessverifiers,xue2025simpletir,dong2025toolstar,yang2025dcpo,yu2025dapoopensourcellmreinforcement,luo2025agentlightningtrainai,dong2025agenticreinforcedpolicyoptimization,su2025toolorchestra,zhou2024archer,prabhakar2025apigenmtagenticpipelinemultiturn,zhou2025sweetrl,xi2025agentgymrl}。与此同时，带可验证奖励的 RL（RLVR）在推理类任务中取得了成功 \citep{shao2024deepseekmath,xin2024deepseekproverv15harnessingproofassistant,Guo_2025,5team2025glm45agenticreasoningcoding}，而 on-policy distillation 则被用于缓解 off-policy 分布偏移 \citep{lu2025onpolicydistillation,zhao2026selfdistilledreasoneronpolicyselfdistillation,xu2025learninginteractionagenticdistillation,hubotter2026selfdistillation}。我们的工作正位于这一交叉点上：我们面向智能体任务，把监督轨迹转写成轮次级 verifier 奖励，从而在不引入独立奖励模型的情况下进行 on-policy 优化。

\subsection{把行为克隆改造成 RL}
离线监督微调（SFT）经常遭遇灾难性遗忘和泛化退化 \citep{luo2023empiricalCF,li2024revisitingCF,imanov2026mechanisticCF,kirkpatrick2017ewc,li2016lwf}，这一现象也与“表层对齐假说”一致 \citep{zhou2023limaalignment,vergarabrowne2026sahcomplexity,raghavendra2024revisitingSAH}。从理论上看，离线模仿学习的次优性会随着任务时域长度呈平方增长 \citep{rajaraman2020towardfundamentallimitsimitation}，因此往往需要通过在线数据聚合引入环境交互才能弥补 \citep{ross2011dagger,swamy2022minimaxoptimalonlineimitation}。关键在于，on-policy RL 能通过保留更广泛的能力来缓解这类遗忘 \citep{shenfeld2025rlsrazoronlinereinforcement,chen2025retainingdoingroleonpolicy}。为了把离线知识迁移到在线阶段，已有方法会将专家演示与 RL 更新结合 \citep{uchendu2022jumpstartreinforcementlearning,hester2018dqfd}、利用部分轨迹前缀 \citep{setlur2026prefixrl}，或者把 SFT token 重新用作 rollout 奖励 \citep{ming2025onetokenrollout}。在这条 SFT 到 RL 的桥梁上，我们的方法进一步针对多轮工具使用场景，提出了基于轮次的 pivot 筛选与功能奖励。
